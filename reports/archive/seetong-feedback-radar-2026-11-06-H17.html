4. 代码定位（详细）

  • 涉及模块：Seetong-App-Android → Seetong5.0ForSeetong/Seetong5.0（Android 原生预览）
  • 关键类与方法：
  • PreviewPlayerView.kt:1782-1795（app/src/main/java/com/seetong/app/seetong/ui/view/video/PreviewPlayerView.kt）——TPS_MSG_P2P_OFFLINE / TPS_MSG_P2P_NVR_OFFLINE 分支，只做 onDevOffLine()
  • PreviewPlayerView.kt:1885-1900（onDevOffLine()）——仅隐藏 loading、清空进度文字、showHelpButton(true)，完全没有置任何「已离线」终态标记
  • PreviewPlayerView.kt:799-832（doRenderTimeout()）——10 秒求流定时器，是否继续重试的第一道门禁
  • PreviewPlayerView.kt:1228（setVideoInfo2）——收 TPS_MSG_NOTIFY_DISP_INFO 时刷新「视频播放中 / xx%」文案
  • device_list/.../VideoPlayerView.kt:73,77,846-878——另一条同类实现（RESUME_PLAY_CHECK_TIME = 9000、RESUME_PLAY_INTERVAL_TIME = 10000）
  • 调用链：

LibImpl.doMsgRspCB(3283-3316) → deviceOffline(dev, dev4gOnline)（LibImpl.java:3093-3134，置 m_status_nvr = Device.OFFLINE 并 refreshDevListByOnlineState）→ sendMessage(TPS_MSG_P2P_OFFLINE) → PreviewPlayerView 消息分支 → onDevOffLine()（仅改 UI 外观）
同时：VideoPlayerView.kt:808 startAutoResumePlay() 起 10 秒定时器 → doRenderTimeout() → 判 m_dev.onLine != Device.ONLINE → LogUtil.i("doRenderTimeout device is offline") 并 return；但定时器本身不停，一旦 m_play 与 m_dev.onLine 出现任意一次回摆，就会走到 pauserPlay() + autoStartPlay() 重新起播，于是 setVideoInfo 又写回「视频播放中」。

  • 关键分支（哪条路径触发本问题）：
  1. LibImpl.deviceOffline() 只把 m_status_nvr 置 OFFLINE（LibImpl.java:3121），没有同步 m_dev.onLine，两者是两套状态；
  2. onDevOffLine() 不打断求流定时器、也不置本地「已离线」标志，m_play 仍为 true；

  • PreviewPlayerView.kt:1885 的 onDevOffLine() 增加终态标志（如 isDevOffline = true），并在 setVideoInfo/setVideoInfo2 入口 if (isDevOffline) return；
  • doRenderTimeout() 的离线早退分支（PreviewPlayerView.kt:802-812）同时 stopAutoResumePlay()，避免无意义重试；
  • LibImpl.deviceOffline() 在置 m_status_nvr 的同时回写 dev.m_dev.setOnLine(Device.OFFLINE)，消除 m_status_nvr 与 m_dev.onLine 的双状态不一致；
  • device_list/.../VideoPlayerView.kt:664-700 与 kmp/.../VideoPlayerView.kt:615 有同构代码，需一并修，避免只修一条入口。

5. 根因结论

  • 置信度：🟢 强
  • 一句话根因：离线事件只改了 m_status_nvr 与界面外观，没有建立「离线终态」并在其上拦住 10 秒求流定时器的重新起播，导致状态文案被 TPS_MSG_NOTIFY_DISP_INFO 反复写回「视频播放中」。
  • 关键证据链：Logan 中 devIsOnline=0 且心跳停 2 天 ⇒ 设备真实离线（服务端事实）＋ TPS_MSG_P2P_OFFLINE 反复上报 ＋ setVideoInfo 在两种文案间 4 秒 3 次循环（客户端事实）＋ 代码里 onDevOffLine() 无终态、doRenderTimeout() 早退但不停止定时器（机制事实），三者互证。
