根因结论

  • 置信度：🔴 弱。
  • 一句话根因：可确认 HarmonyOS 1.1.1.11 在短时间内出现跨机型、跨地区的回放不可用簇；神策显示超时、离线、时间轴失败和存储卡异常并存，端侧日志缺失，当前无法收敛到单一根因。

  • 涉及模块：Seetong-App-iOS/Seetong5.0_ios/Seetong_tps/KMP/View/KMPCloudPlaybackVideoView.m、Seetong-App-iOS/Seetong5.0_ios/Seetong_tps/Classes/TPS/View/IjkPlayerVideoView/IjkPlayerVideoView.m。
  • KMPCloudPlaybackVideoView.m:468-486：播放器完成解析后启动 prepared_fallback，固定等待 kKmpCloudPreparedSuccessFallbackDelay 后直接调用 kmp_resolvePendingPlayCallback:YES。
  • KMPCloudPlaybackVideoView.m:56：该固定等待只有 1.2 秒；在这 1.2 秒内没有首帧时，KMP 仍会收到 success=true，loading 可以提前结束，但画面尚未被证明可播放。
  • KMPCloudPlaybackVideoView.m:870-900：真正的首帧回调能隐藏过渡帧并结算成功；解析完成回调另行启动上述 1.2 秒兜底，两个状态之间没有“已解析但无首帧”的独立中间态。
  • IjkPlayerVideoView.m:707-749：IJKMPMovieFinishReasonPlaybackError 与 IJKMPMovieFinishReasonPlaybackEnded 进入同一续播回调分支，没有把错误原因、底层错误码或失败事件传给 KMP 容器。
  • KMPCloudPlaybackVideoView.m:829-865：ijkViewPlayEndForPlayer 对首帧前结束按失败结算，但随后无条件发送 kmp_cloud_record_complete_event；该事件语义接近“片段播放完成”，不能区分真实结束与播放错误。
  • 调用链：KMP prepareVideo → playVideo → IJK prepareToPlay → 1.2 秒 prepared_fallback 或首帧 → 结束/错误通知 → KMP loading 与续播状态。当前状态机存在“未出首帧但已向业务层成功”和“播放错误被当作结束”的两个可验证风险点。

根因结论

  • 置信度：🟡 中。
  • 一句话根因：iOS 云回放容器允许解析完成后在 1.2 秒无首帧时提前向 KMP 返回成功，同时把 IJK 播放错误与正常结束合并处理，导致页面对真实卡顿、缓冲超时或解码失败缺少准确状态和可回溯证据；这是高度可疑的共同客户端缺陷，但仍需复现确认其是否为 3 名用户的直接主因。
  • 关键证据链：3 名独立用户在同一应用版本、同一晚报告回放卡顿 → 两份 Logan 均证明 App 与设备重连后在线，同时完全没有回放容器日志 → 源码直证无首帧可被 prepared_fallback 标记成功，播放错误被复用正常结束回调。
  • 明确不下的结论：不把所有卡顿归因于网络，不把 error_code=0 / is_success=0 的 236 万条样本解释为失败，也不声称已经复现首帧超时。
