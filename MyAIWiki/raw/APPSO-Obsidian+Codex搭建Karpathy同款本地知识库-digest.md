# 原文摘要 - 用 Karpathy 思路搭一套本地知识库

## 一句话总结

APPSO 团队从实操角度写的"Karpathy 同款本地知识库"完整搭建指南：核心是 3 层结构（素材层 / 笔记层 / 规则层）+ 完整可执行 Prompt 模板 + "AI 持续整理复盘"自动化——让知识库从"收藏夹"变成"AI 可读的个人档案室"。

## 核心观点（6 条）

1. **知识库 ≠ 收藏夹**：文件夹分得再细，找不到 = 没用；问题不是资料少，是没被 AI 读懂，也没变成可调用的个人系统
2. **3 层结构**：
   - 素材层（原始资料原样存，只读不改）
   - 笔记层（AI 提炼结构化 Markdown + 互链）
   - 规则层（AGENTS.md 跨模型可移植的"入职手册"）
3. **核心理念：让 AI 真正了解你**——你平时怎么写稿、喜欢什么节奏、讨厌什么表达、做什么项目、收藏夹反复出现什么主题
4. **三个最明显变化**：
   - 收藏夹能用了（RednoteStar 读小红书收藏夹→结构化笔记）
   - 不用反复解释自己（AI 持续学习"我到底怎么写"）
   - 换模型记忆不消失（资料规则全在本地，跨模型可移植）
5. **自动复盘**：每周一早上扫描脚本初稿→终稿差异，提炼写作规律更新知识库；让知识库从"仓库"升级为"会自我复盘、持续进化的系统"
6. **完整 Prompt 模板**：3 段（"采访你"总结 / 个人知识库架构师 / 工作方式 + 冲突处理）；强调"先问两件事"（存哪里 + 最想要什么）才动手建文件

## 决策树 / 反直觉

- **如果你的知识库只是收藏夹** → 找不到、想不起、用不上 = 没用
- **如果你没让 AI 读懂你** → AI 每次都从零认识你 = 临时发挥
- **如果你只用云端聊天记录** → 换模型 = 记忆清零
- **如果你建知识库不先问两件事（存哪里 + 最想要什么）** → 结构错配、后期推倒重来

## 核心金句（5 条）

1. "别让知识库变成收藏夹。要让 AI 帮你持续整理，让过去积累的内容，在未来真正派上用场。"
2. "它不是凭空猜我是谁。它是在读完一套关于我的资料后，做出的判断。"
3. "记忆不再绑定某一个模型，而是沉淀在你自己的系统里。"
4. "知识库真正开始发挥作用，是在后面反复使用、整理和复盘的时候。"
5. "它不是帮你「存住过去」，而是让过去的积累，继续参与未来的创作。"
