## 一句话

AI-Native SDLC 不只是让 Agent 写得更快，而是以 `intent.md → spec.md → plan.md → 代码/测试 → PR → 事故记录` 的版本化产物串联规划、构建、验证、发布和运维，让每个通过审核的产物触发下一道可审计门禁。

## 五个要点

1. **瓶颈两侧迁移**：代码生成加速后，规划、审查/测试、部署和运维会成为新瓶颈，不能沿用以人工编码速度设计的流程。
2. **提交产物是交接契约**：意图、规格、计划、变更、审查结论和事故记录进入版本控制，既供下一阶段与 Agent 读取，也形成审计链。
3. **阶段由产物触发**：已批准的 intent 触发设计，spec 触发计划，合并 PR 触发流水线，线上控制带突破又形成新的 intent，线性 SDLC 变成闭环。
4. **治理前移并分层**：Skill 把常用策略送进生成阶段；Hook 用确定性规则阻止禁止操作；完整测试和评审留给提交/PR 门禁。
5. **人审查判断，不盯每一步编辑**：人批准意图、规格、计划和高风险发布；Agent 在受限范围内实施、运行验证、处理反馈和维护 PR。

## 六阶段最小产物

| 阶段 | 关键产物 | 人类门禁 |
| --- | --- | --- |
| 规划 | `intent.md` | 目标、受影响系统、约束和开放问题 |
| 设计 | `spec.md` | 策略、品牌、安全、合规和 UX 冲突 |
| 构建 | `plan.md` + 代码/测试 | 改动范围、风险和证明方式 |
| 测试 | Eval/CI/PR 结论 | 行为、风险与策略是否满足 |
| 部署 | 发布与回滚记录 | 高风险变更、灰度和责任人 |
| 运维 | 事故记录与新 intent | 线上事实回流下一轮改进 |

## 五条执行提醒

- 先做能被版本控制和下一位执行者消费的产物，再让 Agent 编码。
- Plan mode 的价值在于把错方向的代价留在文档阶段，而非限制 Agent 的执行速度。
- 对“必须遵守”的策略使用 Hook/CI；Skill 适合建议和一致性，不是安全边界的唯一载体。
- 每个 Agent 改动都要能运行构建、测试、截图或其他外部验证；修复 Agent 不得同时弱化对应测试。
- 先在一个阶段或一个高价值工作流试点，手动触发闭环后再自动化产物触发，不要一次重做全流程。
