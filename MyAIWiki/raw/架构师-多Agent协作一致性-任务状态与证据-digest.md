## 核心观点

1. 多 Agent 的一致性不是让输出相同，而是让任务、事实和状态对齐；推理可以分歧，协议不能含糊。
2. 并行拆分必须由任务依赖驱动，且要用稳定身份、条件认领、租约和唯一约束防止重复执行。
3. Agent 之间传递的不是更长聊天记录，而是包含版本、证据、假设、权限、产物和验收条件的可执行状态。
4. 结论冲突应保留来源、快照和状态，使用版本化结果契约，而不是把自然语言简单拼成总结。
5. 完成是运行时有证据的状态；失败要在子任务层局部重试，写操作必须区分幂等、安全重放和状态未知。

## 7 个分析角度与开头钩子

### 1. 一致性定义
钩子：输出相同不是一致；任务、事实、状态才是对齐对象；协议比意见更重要。
### 2. 并行边界
钩子：并行不是复制任务；依赖决定能否并行；新证据可能要求收回或重拆任务。
### 3. 交接状态
钩子：一句“数据库慢”不是任务；下游需要快照、证据和验收；HANDOFF 要能继续执行。
### 4. 权威事实
钩子：聊天是历史；摘要是工作集；代码、测试、部署和业务库才可能是事实来源。
### 5. 结果契约
钩子：冲突不是错误；来源不同才是风险；候选、已验证、冲突、否决要可区分。
### 6. 完成与验收
钩子：文件变了不代表问题解决；测试通过要带 commit 和报告；完成是状态机状态。
### 7. 失败恢复
钩子：超时不等于失败；整任务重跑可能制造副作用；租约、幂等键和补偿让恢复可控。

## 5 个可执行动作

- 为全局任务和子任务定义稳定 ID、版本、输入快照、状态、尝试次数、租约和产物引用。
- 用结构化 handoff 传递 `snapshot / evidence / assumptions / constraints / artifacts / acceptance`。
- 给结果增加来源、状态和证据引用，禁止未经检查的自然语言总结直接写入共享事实层。
- 将完成条件绑定到可复验命令、退出码、报告、commit 和 Reviewer blocker，而不是 Agent 自报。
- 对副作用动作使用幂等键、远端查询、局部重试和人工补偿入口，明确处理“状态未知”。
