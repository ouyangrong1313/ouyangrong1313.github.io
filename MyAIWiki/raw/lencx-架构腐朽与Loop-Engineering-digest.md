## 一句话总结

> 屎山源于不敢删，架构活于持续排熵；AI Coding 时代代码生成边际成本接近 0，腐朽速率同样翻倍——唯一解药是把架构约束编码到 Loop + CI 里让机器维护。

## 核心观点

1. **架构是"删起来贵的部分"**——五层定义（图 / 决策记录 / 约束 / 运行时 / 删成本），第五层是工程现实最贴的工作定义
2. **腐朽必然性 = 历史负担 + 失败成本不对称**——十年下来祖训变成墙，把系统封死在历史里
3. **重构悖论**：立项永远漂亮，两年后多数人选择绕道，多一层壳包裹旧系统
4. **Linux 模式**：稳定性预算花在系统调用/驱动 API/文件系统语义这些"对外承诺"接口；内部实现可激进重构（外紧内松）
5. **提交即重构**：小步前进 + 主干可编译 + 重构不动语义 + 删前先删死代码 + 命名即文档
6. **守卫自检**：永远 pass 的检查器信息量为零；每条规则配反例测试让检查器证明自己还能失败
7. **删比改更重要**：祖训是软件熵的化石；定期盘点 + 让删变成正常开发动作 + 删前加引用监控
8. **Loop Engineering**：AI Coding 让代码生成边际成本接近 0；架构师的工作从"画图"变成"把约束编码到 Loop"——约束进 Loop，Loop 进 CI，CI 不可绕过

## 5 关键金句

- "屎山源于不敢删，架构活于持续排熵"
- "架构是那些删起来贵的部分"
- "外紧内松。承诺稳定的是接口，不是实现；这是让超大代码库长期演化的关键"
- "一个永远通过的检查，对判断当前代码是否破坏约束几乎没有信息量。它可能表示系统完美，也可能表示检查器早已失效"
- "模型可以忘，流水线不能忘"

## 3 反直觉点

1. 重构立项永远漂亮，两年后多数人选择绕道——多一层壳，问题没消失
2. 永远 pass 的检查器信息量为零——系统完美 OR 检查器早已失效
3. AI Coding 让代码生成边际成本接近 0，腐朽速率同样翻倍——过去因为成本太高不敢做的实验，现在变得可以做，但烂代码也能 prompt 出来
