# Agent能力不足维护代码库 — 原文摘要

## 一句话总结
HumanLayer 创始人德克斯·霍西指出：Agent 能加速单次实现，但在长期迭代的代码库中无法自动维持架构质量；SlopCodeBench 分阶段评测显示最优 Agent 仅通过 16.3% 检查点，"无人值守软件工厂"在复杂系统中尚未成立。

## 核心观点（4 条）
1. **"关灯软件工厂"的诱惑与陷阱**：Agent 把实现从几天缩到几小时，但审查未同比缩短；诱人想法是把审查也交给 AI，但复杂项目的架构退化代价按月/年计。
2. **测试通过 ≠ 可维护**：当前测试只验证本次功能正确，无法预判下月新需求对模块边界的影响；糟糕架构的成本有数月延迟。
3. **SlopCodeBench 实证**：36 任务、196 阶段检查点，要求 Agent 在自己写的代码上连续扩展；最优 Agent 严格通过率仅 14.8%→16.3%，无一完整完成全部任务。
4. **先规划再动手**：影响面大的任务先花 20-30 分钟与 Agent 讨论改法，说清模块划分和提交顺序，可省掉审查时数小时返工；小改动不必过度规划。

## 核心金句（3 条）
- "糟糕架构的成本，是按月、按年计算的。今天没有一个测试，能立刻告诉你这份代码将来是否容易维护。"
- "一次能交卷跑通，和连续几轮都还能改得动，完全是两回事。"
- "这次合并以后，谁还要在这份代码上继续工作？如果答案是整个团队，就该在 Agent 开工前讲清模块和边界。"
