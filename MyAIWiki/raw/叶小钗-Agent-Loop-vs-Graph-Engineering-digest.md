# 叶小钗 Agent Loop vs Graph Engineering - 原文摘要（Raw Digest）

## 一句话总结

**叶小钗对比 Agent Loop 与 Graph Engineering——Loop 是管理层方法论（隐性流程显性化为代码），Graph 是工程架构层（节点之间数据流与依赖关系）；两者不是替代关系，是不同层面回答"怎么让 AI 系统稳定、可控、高效地干活"的同一问题。**

## 核心观点

- **AI 圈炒冷饭**：Prompt/RAG/Context/ReAct/Agent/MCP/Skills/Harness 都是同一概念的再包装
- **Agent Loop 是 AI 原生组织实践**：把"什么情况自动处理、什么情况转人工、谁确认、怎么交接"等隐性规则显性化为代码
- **Graph Engineering 是系统架构层**：节点（Node）=干活的单元，边（Edge）=数据流动的通道，关注数据流 / 依赖 / 容错
- **执行顺序 ≠ 数据依赖**：先后顺序不代表依赖，天气查询和文件总结没数据流动就没边
- **Graph 是退化的 Loop**：线性 A→B→C→D 是退化的图，单点卡住全部得等
- **作者实际判断**：现阶段 Graph 没有太大深入价值，因为不是组织实践方法论，是工程探索，被淘汰概率挺大
- **底层问题不变**：怎么让 AI 系统稳定、可控、高效地干活——技术是手段，解决问题才是目的
