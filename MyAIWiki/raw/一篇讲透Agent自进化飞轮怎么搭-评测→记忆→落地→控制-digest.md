## 一句话

Agent 的自进化不是把一次成功直接写进 Prompt 或 Skill，而是让可信评测产生信号，经受治理的记忆沉淀，再以可回滚候选变更上线，并由人维护评测、权限和方向。

## 五个要点

1. **Harness 是主战场**：相比改模型权重，改记忆、Skill、Prompt、工具配置和工作流更即时、可控、可回滚。
2. **评测是信号源**：它既决定质量门槛，也决定哪些经验可写入、下一轮该改哪里；错误正反馈会持续污染系统。
3. **数据集隔离**：train 用于诊断，val 用于筛选候选，test 用于最终上线验证；生成修改方案的一方不得接触 val/test。
4. **记忆需要治理**：只在有正向证据或明确反例时写入；每条记录必须可溯源、可衰减、可冲突处理、可不读取。
5. **自动化不等于自治**：候选 Skill/Prompt/工作流须经过回归、灰度和回滚；评测器、安全边界、预算和生产权限留在人手中。

## 飞轮与产物

| 环节 | 输入 | 输出 | 不可跳过的门 |
| --- | --- | --- | --- |
| 评测 | 任务轨迹与结果 | 失败归因、可信评分 | 评测集隔离与评估器校准 |
| 记忆 | 已验证正例/反例 | 带来源和有效期的经验 | 准入、冲突、遗忘与预算 |
| 落地 | 系统性失败模式 | 候选 Skill/Prompt/流程 | 独立回归与版本回退 |
| 控制 | 候选与影响范围 | 批准、灰度、冻结或回滚 | 人保留边界和最终裁决 |

## 五条执行提醒

- 优先用确定性规则验证格式、工具调用和产物；语义问题再交给独立评估器。
- 日常跑核心回归，定期跑全量集；同等预算下比较候选，避免用更多 Token 伪造进步。
- 单次成功只算 observation；多次复现且归因清楚后才成为候选经验。
- 候选变更默认不覆盖现网，先在独立验证集和小流量环境中证明没有回归。
- 连续失败不改善时停止自动试错，先检查工具、数据或评测器，而不是继续叠规则。
