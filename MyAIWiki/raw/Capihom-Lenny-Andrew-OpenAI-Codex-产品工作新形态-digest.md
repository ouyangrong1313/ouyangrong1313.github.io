## 一句话总结

实现变便宜后，产品工作的稀缺资源从"工程实现"转向"品味 + 调度能力"——Codex 周活 500 万 / OpenAI 内部 100% 员工用 / 产品流程从 90 份文档倒过来成 90 个原型。

## 核心观点

1. **产品流程倒过来**：过去"先文档后工程"是防风险，Codex 让工程变便宜 → 90 个没有协调的实现尝试同时冒出，团队难题从"谁来写代码"转向"哪部分值得保留"
2. **最贵的是品味 (taste)**：不是审美，是调度能力——90 个尝试里选方向、合并片段、决定主功能；Paul Graham 穿工装短裤也有 strong taste
3. **选对表达媒介**：PRD、原型、artifact 是不同阶段的工具；"代码写出来 ≠ 该上线"，可能只是等下一代模型的 artifact
4. **PM 不能取消**：他明确反对"取消产品角色，所有人都叫 builder"；Codex 侧的工作像"区域防守"——找空白区、把信号引到产品形态
5. **Codex = home base**：不重做 Excel/Premiere，AI 补接口；财务同事用 Excel 插件，Codex 调用；Premiere 剪辑任务 Codex 给自己写扩展改 marker
6. **别和流程绑定，要和结果绑定**：去年 11 月能规划的东西过几个月就不一定；2 月发布的 Codex app 若 11 月准备好结果完全不同——产品团队要"保存好想法等模型跳一下"

## Codex 关键数据

| 维度 | 数字 |
|---|---|
| Codex 使用量增长 | 1 月以来 **6 倍** |
| Codex 周活用户 | **500 万+** |

| Codex 核心团队 | 双位数工程师 + 设计人数 = 工程一半 + 产品人更少 |
| Codex 团队背景 | 很多人是前创始人 / 在大公司做过"像创始人一样"的事 |

## 6 句关键金句

- "实现已经变便宜了，最贵的是品味。"
- "如果实现变得充裕，选择正确的表达媒介就变得很重要。"
- "别执着于现在的流程，要执着于你独特能交付的结果。"
- "如果你要在一个模糊区域里建立产品清晰度，它也许应该是一份文档；如果你要把东西交到别人手里，压测一个交互模式，它就是一个原型。"
- "我听过很多公司说要取消产品角色，这在我看来是个很糟糕的想法。"
- "你要有好奇心，要有一个明确的结果，然后把 Codex 当成平台去试试看会发生什么。风险很低，也就是几个 token。"
