# 原文摘要：别再反复教 Coding Agent：让项目记住自己如何工作的五个步骤

- **作者：** Phodal（Better Harness / QoderAI）
- **原文链接：** https://mp.weixin.qq.com/s/1FrHNkfVpp8CE7keWt_lbQ
- **获取时间：** 2026-08-03 10:29 Asia/Shanghai

## 一句话总结

让 Coding Agent 不被反复教的关键，是让项目自己记住经验——AGENTS.md 给地图、文档接到任务路径、Skill 提炼重复工作、CLI 优先于 MCP、Agent Work Loop + Loop Discovery 让经验沉淀回流。

## 核心观点（5 条）

1. **项目成长 4 阶段表格：** 开工（AGENTS.md）→ 知识路由（核心文档）→ 重复方法（Skill）→ 持续改进（Agent Work Loop）。新增的内容要按这张顺序填，不是写万能 Prompt。
2. **AGENTS.md 是地图不是百科：** 渐进式披露——根目录只放多数任务都需要的入口/命令/风险/文档导航，更详细的架构/设计/工作流通过链接按需读取。Agent 能从代码看出来的不必写。
3. **Skill 探索门槛：** 相似需求 ≥ 2 次 / 高成本高风险 + 可能再发生 / 输入相对稳定 / 步骤能复用 / 结果可检查 / 没被现有文档脚本 Skill 覆盖——六个条件缺一不可。
4. **CLI 优先 MCP 兜底：** Agent CLI 六条（help 发现 / 非交互 / 稳定输出 + JSON / 明确错误退出码 / 超时 / dry-run）；程序能判断的规则归脚本/Hook/CI，不是 Skill 提醒。
5. **写进仓库 ≠ 实践生效：** 等下一次类似任务到来，Agent 能否找到、用上、少一次返工，才决定实践是否值得保留——这是 Loop Discovery 唯一检验标准。

## 关键参数（一张表）

| 阶段 | 产物 | 决策标准 |
| --- | --- | --- |
| 1. 开工 | AGENTS.md | 短/准确/可执行/渐进式披露 |
| 2. 知识路由 | 核心文档 + 读取条件 | "改什么读什么"，不是链接列表 |
| 3. 重复方法 | Skill | 探索门槛 6 条 |
| 4. 工程接口 | CLI > MCP | CLI 六条 / 程序判断归脚本 |
| 5. 持续改进 | Agent Work Loop + Loop Discovery | 5 类沉淀位置决策 |

## 速查：5 类沉淀位置决策（Loop Discovery）

| 信号类型 | 沉淀位置 |
| --- | --- |
| 稳定事实 | AGENTS.md 或核心文档 |
| 重复方法 | Skill |
| 确定性操作与检查 | CLI / 脚本 / Hook / CI |
| 外部资源发现 + 持续交互 | MCP |
| 高风险、不可逆操作 | 权限边界 + 人工确认（不沉淀） |

## 关键金句（5 条）

1. "一个 Agent 友好的项目，不是安装了多少工具，而是项目知识能否被发现，流程能否被执行，结果能否被验证，经验能否进入下一次任务。"
2. "Agent 能从代码中看出来的内容，没有必要再写一遍。真正值得写进去的，是它看不出来、却很容易猜错的事实。"
3. "只在 AGENTS.md 末尾放一串链接还不够。更有效的写法，是同时给出读取条件……这一小句把文档接到了具体任务上，也形成了一条最小的知识路由。"
4. "Skill 可以理解为一份由 Agent 按需加载的工作手册。它回答的是一种任务应该怎样完成：何时触发、需要哪些输入、按什么顺序执行、产出什么结果、如何验证，以及遇到什么情况应该停止并交给人。"
5. "所谓持续改进，不是不断增加配置，而是让这一次任务留下的东西，真正帮助下一次。"

## 反直觉点（3 条）

1. **AGENTS.md 越短越好**——根目录只放入口/命令/风险/导航，不是把架构/设计/工作流全搬进来；详细文档按需链接。
2. **CLI 优先于 MCP**——已有脚本或命令行的项目，先把 CLI 整理成稳定接口，不必立刻增加 MCP Server；MCP 只在外部系统缺命令行入口、需要结构化资源发现或持续交互时启用。
3. **写进仓库 ≠ 实践生效**——下一次类似任务到来，Agent 能否找到、用上、少一次返工，是唯一检验标准；否则就删掉或改写。
