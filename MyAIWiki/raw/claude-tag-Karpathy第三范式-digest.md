# Claude Tag - Karpathy 第三范式 拆解

## 核心观点

1. **Claude Tag = Claude 进 Slack 频道协作**：Anthropic 把 Claude Code 的能力搬进 Slack，多人协作 + 上下文积累 + ambient 主动模式 + 异步执行，**内部已贡献产品团队 65% 代码**。
2. **Karpathy 的"三种范式"理论**：大模型 UI 从「网站」（被动访问）→「桌面 App」（本地执行）→「自洽实体」（持续在线、异步、组织级上下文）。第三种范式已来。
3. **频道即权限边界**：管理员按频道隔离工具/数据/记忆，token 限额 + 全链路审计 → 让企业敢用。
4. **三争议（评论区）**：① 价值观不可调教 ② 厂商 agent 归属权 ③ openclaw 等开源替代的迁移成本警钟。
5. **本质：Agent 嵌入团队工作流的范式革命**——不再是"人用 AI 工具"，而是"AI 作为一个永不睡觉的同事在 Slack 里接活"。

---

## 7 个分析角度 + 钩子库

### 角度 1：三种范式的代际跃迁
- 钩子 A1：20 年我们访问 Google，未来我们"邀请"一个 AI 进团队群 —— Karpathy 说这就是第三次大改。
- 钩子 A2：网站 → App → 数字员工，这就是 Karpathy 给出的 LLM UI 三段论。
- 钩子 A3：当 AI 不再等你 @ 它，而是主动帮你跟进那些冷掉的线程 —— 范式就变了。

### 角度 2：Claude Tag 的工程亮点
- 钩子 B1：一个人人都能 @ 的 Claude，让团队里每个停下手的人都能无缝接上 —— 这是异步协作的最大利器。
- 钩子 B2：ambient 模式让 AI 主动出手跟进冷线程 —— 这是 Slackbot + Agent + Cron 的合流。
- 钩子 B3：频道即权限边界 + 记忆隔离 = 销售记忆不会污染工程记忆 = 企业敢用的前提。

### 角度 3：65% 代码贡献意味着什么
- 钩子 C1：当 AI 写了你团队 65% 的代码，下一步是什么？—— 是 AI 写产品指标、写工单回复、写故障复盘。
- 钩子 C2：Anthropic 自己都不用担心"AI 替代人"，因为他们已经在做了 —— 这就是 Agent 时代的真相。
- 钩子 C3：内部先行先试 → 65% 通过验证 → 对外开放 beta —— Claude Tag 的"自信"是有数据背书的。

### 角度 4：异步 + 自主日程 = 真正的"数字员工"
- 钩子 D1：派完任务你能去开会、吃饭、睡觉，几小时后 Slack 线程里有结果 —— 这就是 Karpathy 说的"自洽实体"。
- 钩子 D2：AI 给自己排日程 + 连着几小时几天推进项目 —— 这不是 chatbot，这是 scheduler + executor。
- 钩子 D3：把"派活→等回"变成"派活→异步收件" —— 这才是异步协作该有的样子。

### 角度 5：归属权之争 —— 厂商 agent vs 本地 agent
- 钩子 E1：Claude Tag 是厂商 agent 进你的频道；openclaw 是你 agent 进自己的频道 —— 所有权差十万八千里。
- 钩子 E2：换 SaaS 是按月付费；换 Agent 是迁移整个组织记忆 —— 后者成本是前者十倍不止。
- 钩子 E3：把公司记忆锁死在一实验室，是 2026 年最大的技术债 —— 别再重复 2022 年锁死云数据库的错误。

### 角度 6：价值观不可调教——同事还是工具？
- 钩子 F1：你没法用职级压它、用社交压力影响它 —— 一个"不受职场规则约束"的同事，会颠覆多少协作惯例？
- 钩子 F2：Anthropic 的价值观写在 Claude Tag 的骨子里 —— 这到底是产品优势还是产品缺陷？
- 钩子 F3：AI 同事的"文化"是 Anthropic 定的 —— 未来企业招聘 AI 时，要不要先面试"价值观契合度"？

### 角度 7：开源替代品的崛起 —— openclaw 的信号
- 钩子 G1：评论区一半人在推荐 openclaw —— 当一个厂商功能足够大，开源方案就会爆发。
- 钩子 G2：你以为是"AI 进 Slack"，其实是"AI 团队记忆层"——这一层，必须你自己掌控。
- 钩子 G3：当 Karpathy 给厂商方案背书时，开源社区就开始造替代品 —— 这是 2026 年的新常态。
