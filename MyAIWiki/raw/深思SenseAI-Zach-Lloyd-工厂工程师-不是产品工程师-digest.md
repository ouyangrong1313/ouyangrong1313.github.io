# 工厂工程师,不是产品工程师 — Digest

## 一句话总结

> **"工程师的活,从造车变成了造工厂"** — Warp 创始人 Zach Lloyd 在内部备忘录里宣布团队从"产品工程师"升级为"工厂工程师";**成功 = 工厂效率 ≈ 出货产品 / (推理成本 + 人的时间成本)**;**人在环里 = 需要复盘的失败**;8 步流水线(分诊→spec→实现→review→验证→CI/CD→上线→监控)+ **递归自我改进**。深思圈主编反对无脑造工厂,主张**看任务分工** — 工厂自动化"怎么做",人攥"做什么"和"为什么"。

## 三大主张(原文核心)

1. **从造车到造工厂**:工程师不再做产品,造一台"做产品的东西";成功 = 工厂效率 = 出货产品 / (推理成本 + 人的时间成本)
2. **软件生产从 R&D 变 COGS**:从固定研发开支 → 可变成本;老板像盯工厂良率一样盯;"给所有工程师无限 token 预算的日子结束了"
3. **人在环里 = 失败**:"每用一次人在环里的 agent 写代码,都要当成需要复盘的失败";递归自我改进 = 黄金路径

## 8 步流水线 + 关键公式

```
分诊 agent → spec agent → 实现 agent → code review agent → 验证 agent(computer-use)→ 人审 → CI/CD → 监控 agent(闭环)
```

```
工厂效率 ≈ 出货产品 / (推理成本 + 人的时间成本)
```

**"人"在分母里,是要被往下压的成本。**

## 深思圈主编立场(关键反转)

**两个创始人屁股都得扣掉一点(都在卖自己的东西)**。真相是**看任务**:

- **能被机器校验对错的活**(怎么做:实现/验证/监控)→ 交给工厂,Lloyd 对
- **靠判断定生死的活**(做什么:做哪个/产品观点/为什么)→ 留住人,Bakaus 对
- 工厂自动化"怎么做",**人依然攥"做什么"和"为什么"**

## 最反直觉的洞察(深思圈主编补刀)

> **你把"怎么做"自动化得越彻底,整盘棋,就越押在那一件工厂永远没法替你决定的事上 —— 什么,才值得做。**

- Lloyd 把"成功"定义成"自动出货的比例",但他自己承认"出货的产品是不完美的价值衡量"
- 1300 个"可实现"待办的真正问题不是"谁来实现" — 是"哪些根本不该做"
- **无脑地、更快地造更多,从来不是战略**

## 关键金句

- **"给所有工程师无限 token 预算、去玩交互式 agent 的日子,要结束了"**
- **"我们现在是工厂工程师,不再是产品工程师了"**
- **"以后你每用一次'人在环里'的 agent 去写代码,都要把它当成一次需要复盘的失败"**
- **"短期一定会很痛,我们必须逼自己去经历这种痛,才能搞清楚怎么把它自动化掉。我们不做,别人会做"**
- **"工厂效率 ≈ 出货的产品 / (推理成本 + 人的时间成本)"**
- **"你把'怎么做'自动化得越彻底,整盘棋,就越押在那一件工厂永远没法替你决定的事上"**
