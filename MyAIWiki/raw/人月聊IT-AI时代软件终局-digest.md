## 核心观点

1. **AI改变的不只是软件的使用方式，也可能改变软件的构建和交付形态。** 作者认为，RPA、Computer Use 等通过界面兼容存量系统的方式更像过渡方案，目标态可能转向 Agent 直接调用能力接口；这是作者判断，不是已验证的行业共识。
2. **UI的职责可能从日常录入与查询转向例外处理和监督。** 当采集、查询和动作能由 AI 通过 API 完成时，界面仍可承接审批、审计、异常处理、编辑和人工接管。
3. **应用的数据抽象可能从表结构转向业务对象契约。** 作者设想逻辑上以对象和语义组织数据，底层再按事务或分析访问模式使用表、文档、图、向量或列存；这不等于事务、一致性和结构化数据不再重要。
4. **软件可能由静态制品变成受治理的自进化 Agent。** 重复任务沉淀为 Skills；未覆盖任务可生成新能力，经过验证后再复用。评测、权限、灰度、回滚和审计是这一循环成立的前提。
5. **企业应用架构可能从业务烟囱转向能力层与编排层。** 能力层暴露可复用 API 或 Skills，编排层根据意图和场景组织调用；共享语义、工作流约束和治理决定编排是否可靠。
6. **本体模型被作者视为语义底座，而不是静态知识图谱。** 它要连接业务对象、关系、规则、约束和动作，并与能力契约衔接，让 Agent 知道接口代表什么、何时可用及如何验证结果。
7. **文章的核心命题是“能力可编排、代理可信、语义统一”。** 文章提供的是方向性架构主张，没有给出对照实验、迁移数据或生产案例来证明这就是软件行业的唯一终局。

## 7 个分析角度与开头钩子

### 1. 文章重新定义了什么问题

- 如果 AI 只是多加一个聊天框，软件的底层形态其实还没有改变。
- 这篇文章真正追问的不是“AI 能不能写软件”，而是“软件还要不要保持今天的形状”。
- 当执行入口从人转向 Agent，软件设计首先要重想的可能不是模型，而是能力和语义。

### 2. UI消失还是职责迁移

- AI 时代最可能先消失的，不是界面，而是每次都要人亲手走完的固定录入路径。
- 一个表单页面的价值，取决于谁在操作：人、Agent，还是两者都需要。
- 界面如果不再负责重复操作，它还应该负责什么？异常、审批和接管可能是答案。

### 3. 数据抽象从表走向对象意味着什么

- 数据库的表不会因为 Agent 出现就失去价值，但它可能不再是应用对外表达业务的中心语言。
- 如果一个业务对象总要经过多表拆分再拼回，Agent 的接口也许应该停在对象语义这一层。
- 真正的变化不一定是换数据库，而是让 Agent 面对稳定对象契约、让底层存储保留实现自由。

### 4. “软件日抛”之后怎样留下复利

- 动态生成软件只解决了“这次怎么做”，技能沉淀才回答“下次怎么不重做”。
- 一次性生成看起来快，能通过验证并被重复调用的能力才会形成积累。
- Agent 生成新能力之后，最关键的一步不是保存代码，而是验证、授权并决定能否复用。

### 5. 企业架构如何从烟囱转向能力编排

- 企业系统不会因为加了一个通用 Agent 就自动消除信息孤岛。
- 把旧系统压成能力提供点之后，跨系统协作仍然需要统一的对象、规则和数据语义。
- 通用 Agent 是入口，稳定可组合的能力和工作流才是它背后的工程底座。

### 6. 本体为什么是“有API”之后的问题

- API 能被调用，不代表 Agent 知道它描述哪个对象、受什么规则约束、什么结果才算完成。
- 本体的价值不只在关系图，而在于让对象、行为、约束和业务经验成为共同语义。
- 当接口数量变多，真正的瓶颈可能从“能不能调”变成“调得是否有业务含义”。

### 7. 如何验证这幅终局图景

- 趋势判断最容易跳过的一步，是拿一个真实流程比较新旧方案的成本和失败方式。
- 在迁移 UI 或数据库之前，先找一个重复任务验证接口契约、权限边界和人工接管是否成立。
- 软件会不会自我进化不是口号问题；看它能否通过评测、回滚和审计，才是工程问题。

## 机制解释与替代解释

- **可能的作用机制：** 当业务数据可以机器读取、动作可以通过稳定接口执行，人工录入界面的边际价值会下降；但例外处置、授权和责任确认仍需要可见的人机控制面。可复用 Skills 减少重复生成，语义模型补足 API 的业务含义，治理机制则约束动态能力的副作用。
- **替代解释：** UI 和关系型数据库可能长期保留核心职责。审计、可访问性、精细编辑、事务一致性与成熟运维都能使预设界面和结构化存储继续有价值；Agent 也可能作为现有系统之上的编排层，而非取代应用和数据平台。

## 证据边界

- “软件与 IT 咨询进入夕阳期”的宏观判断由作者提出；文章提到埃森哲拟退出大中华区，但该单一公司动向不能独立证明整个行业或就业需求的长期趋势，本条未独立核验该背景。
- “无预设 UI”“对象中心存储”“软件自进化 Agent”均为架构设想。文章未提供实施系统、基准指标、成本对比、迁移路径或生产效果数据。
- Skills、MCP 和统一语义可能降低集成摩擦，但不自动保证接口正确、数据一致、权限合法或工作流安全；这些仍需逐场景设计和验证。
