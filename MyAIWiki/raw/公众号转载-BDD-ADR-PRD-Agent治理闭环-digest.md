# 拆解：BDD+ADR+PRD — 让 Agent 遵守规范的闭环方法

> 原文章位置：`raw/inbox/2026-07-01-公众号转载-BDD-ADR-PRD-Agent治理闭环.md`
> 拆解时间：2026-07-01
> 拆解人：Claude

---

## 一、核心观点（5 条）

1. **AI Agent 的知识失忆是工程问题，不是模型问题** —— 20-50 次 context compaction 后，"为什么"会被系统性地遗忘，必须把"为什么"从模型记忆里搬进 linter / CI / 文档契约，才能跨压缩周期存活。
2. **规范必须"可执行"，否则就是建议** —— 50+ 条 ADR 躺在 Confluence 里等于零；只有当 ADR 被翻译成 ESLint/CI 规则并强制执行时，Agent 才"不得不"遵守。
3. **文档受众的扩展倒逼文档极简化** —— 文档要同时被人和 Agent 阅读，冗余背景故事是负债，最小可读版本（PRD 三件事）反而最耐久。
4. **BDD 的核心价值是"双轨制"** —— 一份 Gherkin 脚本同时是规范和测试，把"spec 写了但没人验证"的循环闭合掉——这是"测试代码也是规范"的真正落地。
5. **问题不能等发现，要让"问题不可能发生"** —— 闭环执行（Git Hook → CI → Linter → Agent 自动修复）把治理从"巡检"升级为"编译错误"。

## 二、7 个分析角度 + 钩子

### 角度 1：5 只猴子隐喻 —— 知识如何被压缩失忆

> 用经典心理学实验做引子，**焦虑共鸣 + 好奇心循环**双重触发

- 🪝 五只猴子在笼子里被替换，没有一只"原始猴子"在场，但暴揍碰香蕉者的规矩被原封不动地保留。AI 写代码就是这个状态——你继承的"风格"已经没人能解释。
- 🪝 你团队里 90% 的"代码约定"已经没人记得为什么了。AI Agent 在第 3 轮迭代后，同样会开始盲从这些无主规则。
- 🪝 这个实验解释了为什么 LLM 写 50 行代码只要 30 秒，理解 50 行代码为什么这么写要 3 天。

### 角度 2：ADR 的真正革命不是"写文档"，是"写可被静态检查的合同"

> **反常识 + 权威背书**——颠覆大家对 ADR 是"软规范"的认知

- 🪝 你那 50 条 ADR 在 Confluence 里躺了多久？Cichra 的解法是：把每条 ADR 翻译成一条 ESLint 规则，违规时直接报"ADR-007 violated, see ..."。
- 🪝 当年我们写 ADR 是为了"留底"，真正的目的是"被强制执行"。前者是 Wiki 范式，后者是 Compiler 范式。
- 🪝 ADR 不进 linter，等于没写。这条规则值得打印出来贴在工位上。

### 角度 3：PRD 的极简三件事 —— 文档冗余是 Agent 时代的负债

> **对比冲突**——传统 PRD（几十页）vs 极简 PRD（三件事）

- 🪝 10 页 PRD 写得很完整，但 6 周后没人（包括你）会读。3 句话的 PRD 才是 Agent 时代的工程交付物。
- 🪝 文档受众从"人"扩展到"Agent"的那一刻，背景故事就成了反模式。Agent 不需要 why-you-decide，只需要 what-to-build。
- 🪝 PRD 越短，被读的概率越高；ADR 越短，被引用的概率越高；测试越少，被执行的概率越高。这是个反直觉但稳定的规律。

### 角度 4：BDD + Cucumber —— 规范和测试的二合一

> **好奇心循环 + 对比冲突**——AI 写的测试为啥读不懂？BDD 怎么解决

- 🪝 比 AI 写代码更难的是读 AI 写的测试——前者起码能跑，后者连"测的是啥"都得猜。BDD 的 Gherkin 句法让测试代码本身变成产品规范。
- 🪝 60 年软件工程最大的浪费是：spec 写了一份，test 写了一份，两者对不上就没人发现。BDD 用同一份文档闭合了这个循环。
- 🪝 未来 5 年，AI 写的测试代码会成为知识资产的最大黑洞。BDD 是给这个黑洞的第一个补丁。

### 角度 5：闭环执行 —— 让"问题不可能发生"

> **权威背书 + 反常识**——把治理从"巡检"升级为"编译错误"

- 🪝 很多团队的 CI 是"事后发现"，而 Cichra 团队做到的是"提交即拦截"。差异是：前者依赖人 review，后者把 review 写进 linter。
- 🪝 "让问题不可能发生"是软件工程的圣杯。CD 流水线、依赖审计、ADR 强校验——都在朝这个目标走。
- 🪝 当 Agent 提交代码 → 被拒绝 → 自动收到"哪里违规 + 看哪条 ADR" → 自己修复 → 重提——这个循环就形成了 Agent 时代的"自我纠错飞轮"。

### 角度 6：20-50 次压缩 —— 知识资产化是 Agent 时代唯一解

> **焦虑共鸣 + 数据冲击**——为什么这次不一样

- 🪝 一个 AI session 经历 20-50 次 context compaction 后，能存活的不是"模型记住了什么"，而是"系统里还剩什么"。后者靠 ADR/PRD/BDD 撑住。
- 🪝 5 年前我们说"文档很重要"，那时候是说给人听；今天说"文档很重要"，是说给 LLM 听。听众变了，文档形态必须跟着变。
- 🪝 模型越来越强 ≠ 知识越来越稳。压缩的次数只增不减。知识资产化是唯一对冲。

### 角度 7：方法论落地 —— "最小可用版本"四步走

> **实操 + 步骤拆解**——今晚就能动手的版本

- 🪝 不需要先写 50 条 ADR。先写 3 条，配 3 条 linter 规则，违规时自动指向文档——这套闭环一周内能跑起来。
- 🪝 Seetong 三端 + 2 个 C/C++ SDK 的工程治理，可以直接抄这套思路：用 linter 把"为什么"嵌进编译错误里，比写 50 页规范有效。
- 🪝 Agent 治理不是"加个 Agent 监控系统"，是"把规范变成机器可消费的契约"。前者是后视镜，后者是前轮。
