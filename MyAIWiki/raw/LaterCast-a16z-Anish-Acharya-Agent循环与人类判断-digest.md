# a16z 合伙人：当 AI 能让业务自己跑起来，人该做什么？ - 拆解

- 对应原文：[[LaterCast-a16z-Anish-Acharya-Agent循环与人类判断]]
- 来源：微信公众号「晚点再听LaterCast」；作者：Capihom；原始内容：Lenny's Podcast 对话 Anish Acharya
- 文章性质：播客二手整理与投资人观点；公司案例、效率数据、产品案例和模型体验均未独立核验。

## 一句话

Agent 循环可在明确目标和可验证反馈下持续执行、检查和优化，但它只能高效爬当前那座山；人仍需选择山、识别平台期、设定风险与价值尺度、把人工教练介入沉淀为系统经验，并以真实项目形成模型品鉴能力。

## 五个核心观点

1. **两层 AI 采用**：先提升当前岗位工作，再重组跨岗位工作流；给每人助手不等于完成组织改造。
2. **可审查循环**：Agent 任务应连接执行、验证、审批和通知，高风险动作保留确认，低风险动作才可能自动推进。
3. **局部最优平台**：循环擅长沿既有方向反复试验，但目标错误或探索枯竭时，人需要提出新假设、换坡或重设约束。
4. **教练式回写**：人工介入不只解决个案，还应识别知识/数据/工具缺口并回写系统，减少同类问题反复升级。
5. **价值驱动品鉴**：模型选择应结合任务收益上限、成本、风险和可验证性；通过同一真实项目反复试用，比单看榜单更能认识能力边界。

## 七个分析角度与开头钩子

### 1. 为什么助手不等于组织改造
- 给每个人配 AI 后，工作为什么仍可能原地不动？
- 当前岗位提效和跨部门工作流重组，差在哪一层？
- 谁需要亲自理解 Agent 能接到哪一步？

### 2. 怎样把一个 bug 接成循环
- 客户报 bug 后，哪些步骤可以连续交给 Agent？
- 高风险修改和低风险修改，怎样走不同的审批路径？
- 工程为什么比某些业务场景更适合先跑自动循环？

### 3. 循环为什么会卡在平台期
- 多做十个版本，为什么可能仍在同一个局部最高点？
- Agent 能优化方向，谁来决定方向对不对？
- 什么时候该给循环加算力，什么时候该换山？

### 4. 怎样让人工帮助不白费
- Agent 叫人帮忙后，怎样保证下次不会重复叫人？
- 人工介入应该识别知识缺口、数据缺口还是工具缺口？
- 哪些处理过程值得被沉淀为可复用经验？

### 5. 模型选型为什么不只看聪明程度
- 财务结账和产品机会发现，为什么不能用同一模型标准？
- “把事情做好以后值多少”怎样影响模型预算？
- 为什么同一客服工单有时值得更强的模型？

### 6. 消费 AI 还缺什么
- 用户未必想要更好的表格，那他们想打开什么？
- 聊天框和短视频之间，AI 交互还有什么空间？
- 为什么产品效率高，却可能没有理由让人留在生活里？

### 7. 个人怎样建立模型判断
- 为什么最好的模型品鉴方法是做同一个真实项目？
- 每周完成一件小事，怎样比追榜单更能看清能力边界？
- 一个不商业化的家庭项目，能带来什么学习？

## 最小实践

1. 为一个高频、可验证、可回滚的流程定义循环：触发、输入、执行、验证、风险分级、人工审批、通知和异常升级。
2. 给每条循环同时记录目标指标、长期反指标和“何时换方向”的条件，防止局部优化被误作整体进步。
3. 将人工接管归因到知识、数据、工具、权限或策略缺口，并把经过审核的修复写入规则、数据或 Skill。
4. 按任务价值上限、错误代价、延迟和成本选择模型，不将一个部门或一种任务压成单一模型决策。
5. 选一个稳定的个人/团队项目，连续四周用不同模型跑完整流程，记录输出、返工、验证通过率和人工判断点。
