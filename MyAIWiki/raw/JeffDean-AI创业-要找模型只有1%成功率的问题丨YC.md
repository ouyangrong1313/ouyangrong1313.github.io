"去找模型成功率只有 0% 或 1% 的问题，不要选已经能做到 20% 的问题。"


"如果你真正理解数据，就应该能把它压缩得很好。"


"你越清楚自己要什么，Agent 就越有明确的准则可循。"

Jeff Dean 参与创建了 MapReduce、Bigtable、TensorFlow、TPU 和 Gemini。今天许多习以为常的计算基础设施，都能追溯到他和同事当年的一次判断。这次对话里，他把话题落到了 AI 系统的真实限制上。Agent 能连续工作多久，推理为什么受制于数据搬运，小团队该挑什么问题，都是他逐一回答的工程问题；写代码越来越便宜以后，创始人手里还会剩下一项更难复制的能力。对正在用 AI 做产品的人来说，这更像一份选题与工程检查表。

AI 已经能做多长的任务？

2025 年 5 月，Jeff Dean 曾判断 AI 已接近初级工程师的水平。一年后回看，他觉得这个判断大体准确，低估的部分是复杂任务能力增长得更快，Agent 在编程以外的领域也开始显出价值。现在已经有人让系统连续运行数天甚至数周，把一套软件改写成另一种语言，并以安全性或性能为目标反复修正。

"人们还没完全意识到，Agent 可以在一个问题上连续运行数天或数周，并完成非常复杂的任务。"

任务运行数天以后，推理速度就会直接改变产品形态。今天大家已经习惯等模型吐字，Jeff Dean 却让现场想象另一种情况。如果推理延迟改善 50 倍，Agent 就可以用更密集的试验寻找答案，许多原本需要排队执行的操作也能进入即时交互。到那时，用户感受到的会是一套持续工作的系统，而非隔几分钟才返回一步的工具。

先算清楚数据搬运的代价

TPU 的起点是一道算术题：2013 年前后，Google 的深度学习语音识别把错误率降了一半，相当于几个月走过旧系统二十年的改进。质量上去之后，使用量必然增加；假设每位 Google 用户每天只对手机说三分钟，支撑语音识别所需的服务器规模就可能翻倍。CPU 扛不住这个成本，团队于是为低精度稠密线性代数设计专用芯片。

"这颗芯片的能源效率比当时的 CPU 和 GPU 高 30 到 80 倍，延迟也低了 20 到 30 倍。"

这段历史对今天仍有用，因为 AI 系统里昂贵的环节经常藏在模型之外。完成一次乘法大约消耗一个皮焦耳，把数据从高带宽内存搬进处理器，能耗可能高出一千倍。批处理可以摊薄这笔账，可大批量又会拖慢即时响应。数据移动路径没变，仅仅换个更大的模型，账单不会自己消失。

Jeff Dean 那份著名的“工程师该知道的延迟数字”，到了 AI 时代也该换一批指标。团队需要知道加速器主内存到片上内存的带宽、一次乘法的能耗、芯片间互联能连多少设备，以及规模从 500 颗扩到 1 万颗芯片后，网络带宽会掉到什么程度。这些数字会直接限制架构选择，产品层的等待时间只是它们最终露出的结果。

上下文工程，普通团队也能参与

训练前沿模型需要大量算力和数据，围绕模型搭系统的门槛低得多。一个可用的 Agent 还需要检索、工具、记忆和任务编排。训练数据被揉进数千亿参数里，模型很难辨认某条知识来自哪里；放进当前上下文的信息则清楚得多，它可以据此决定下一步调用什么工具，也可以同时试几条路径，再比较哪一条有效。

这也解释了他为什么把模型看成整套系统中的一个部件。模型参数吸收了海量训练数据，却未必能为眼前任务取出最合适的部分；上下文可以把相关资料摆到它面前，工具则让它查询新信息并验证动作。开发者用现成 API 就能反复调整这套组合，门槛远低于重新训练一个基础模型。

"我们只是把人会采用的方法，写成模型可以使用的形式。"

Jeff Dean 和 Sanjay Ghemawat 就做过一次。他们常要优化 Google 内部会在数百万个进程里运行的底层数据结构，于是写了一项 Skill，教 Agent 建立微基准、修改代码、重跑测试、查看缓存占用，再按测量结果继续迭代。两人还公开了一份约 30 页的性能优化文档，有人把内容整理给模型后，模型分析代码性能的能力随之提高。资深工程师原本靠经验掌握的操作顺序，就这样变成了一份团队可以反复调用的文件。

Agent 跑偏后，别只改提示词

不少 Agent 在前十次工具调用里表现不错，到了第三十步或第五十步就开始失控。Jeff Dean 的解释是，模型走到了训练分布之外：它越偏离熟悉的任务，错误越容易累积。Skill 和操作提示能把它留在较熟悉的路径上，内部日志、代码评审或性能测量这些专有工具，也能通过清楚的使用说明接进工作流。

"可以让多个 Agent 尝试不同方案，再由另一个模型判断哪些方向更有希望。"

更长的任务还需要一套搜索机制：多个 Agent 分别推进不同方案，评估器保留有希望的分支，丢掉明显走偏的路径，这相当于用推理时算力换可靠性。如果流程总在固定步骤出错，团队就能沿着失败位置补上评估标准、工具说明或回退路线，让下一轮运行少走一条弯路。

创业选题，先用 1% 规则筛一遍

在谈 1% 规则前，Jeff Dean 先放了一个更个人的条件：创始人得真心想做这件事，也确信它解决了一个有用的问题。两三个人盯住一个具体领域，可以把界面、准确率和使用体验磨得很细；代价是基础模型每天都在扩大覆盖面，今天成立的产品优势，半年后可能只剩一层薄包装。

Google 会继续扩大通用模型的能力边界，小团队要避开六到十二个月后就会被基础模型覆盖的功能。Jeff Dean 给了一个可操作的筛法：拿当前最强的通用模型测试你的目标任务。如果它偶尔已经能完成 20%，说明能力正在出现；若成功率仍在 0% 到 1%，创业公司才有时间建立产品、数据和分发上的优势。

"去找模型成功率只有 0% 或 1% 的问题，不要选已经能做到 20% 的问题。"

可守住的空间常来自两类资产：第一类是通用模型接触不到的数据，比如用户自己的资料和组织内部记录；第二类是窄而难的专业任务，团队可以用更小的专用模型做到更高准确率。AlphaFold 只处理蛋白质折叠，却为生物研究提供了通用模型难以替代的工具。创始人需要把“我知道什么独有信息”和“哪项任务能做得更稳”落实到真实数据上。

代码变便宜后，规格和品味更贵

同时管理几十个 Agent，首先考验的仍是能否把需求写明白。人类工程师会带着组织背景追问，Agent 更容易根据含糊描述自行补全，结果通常和委托者脑中的答案不一样。把 Python 项目完整迁移到 Go 之所以适合今天的模型，正因为原项目、测试和行为结果共同构成了非常详细的规格，模型可以逐项比较两个版本。

"你越清楚自己要什么，Agent 就越有明确的准则可循。"

当执行力供应充足，决定做什么会占据更大的价值。Jeff Dean 把这种能力称作品味：研究者工具再多，选了无聊的问题，也只能漂亮地完成一项影响有限的工作。他建议写下未来十二个月可能重要的多个方向，即使只做其中一个，也在一年后回看其余判断。别人做成了哪些，哪些至今无人碰，都能为下一次选择多添一份真实样本。

偶尔把行业前提倒过来想

Jeff Dean 最近和同事做过一个古怪的思想实验。芯片行业用了六十年降低晶体管错误率，默认同一设计制造出的每颗芯片都该完全一致；大型分布式系统却早已接受磁盘和机器随时会坏，再用副本、纠删码和跨机架部署保证数据安全。那么，如果晶体管每天出错二十次，而非数百万年才错一次，芯片会如何设计？信号也许需要沿多条冗余路径同时传递，制造方法可能随之改变。

"如果用每天可能出错二十次的晶体管构建系统，会发生什么？"

多数思想实验最后不会落地，偶尔会冒出 MapReduce 这样的东西。早期 Google 的网页抓取和索引代码混着并行、检查点和容错逻辑，实际计算反而被埋住。Jeff Dean 等人把 Map 和 Reduce 抽成上层接口，把可靠性放进底层库，于是大量计算任务都能复用同一套机制。他们先重新描述了要完成的计算，原来缠在一起的实现细节才有了清楚边界。

这个设想也让人想到大脑：神经信号并不总能可靠地抵达目的地，重要信息会通过多条通路传递。Jeff Dean 没有断言芯片行业应该照搬这种结构，他只是提醒团队隔一段时间重查一次共识。旧做法沿用五十年，可能确有充分理由；先把理由找出来，仍比默认它永远正确更有收获。

把实验循环缩短，研发方式会跟着变

Jeff Dean 对 2027 年的预测，是机器学习系统会更频繁地参与改进自身。系统接到高层目标后拆成子问题，为每个子问题提出实验、执行并测量结果，再把有效方案组合起来。适合这种自动循环的领域都有一个共同条件：结果可以衡量。如果评估一次太慢，还可以先学习一个速度更快的近似评估器。

"一个原本要运行整晚的模拟器，被做成了快 30 万倍、准确度接近的神经网络近似模型。"

他的同事曾用量子化学模拟数据训练近似模型，把一次分子性质评估从整夜计算缩短到几乎可以批量运行。原来要半年筛选的一千万个候选，可能在午饭时间处理完，类似循环也会进入模型架构、材料和芯片设计。Jeff Dean、Geoffrey Hinton 与 Oriol Vinyals 在 2014 年写的模型蒸馏论文曾被会议拒绝。今天这项方法已经用于 Gemini Flash，实际服务需求给了它另一种检验。

他还留下一道没有答案的问题：前沿模型看过的数据，可能是一个人十八岁前接触信息量的一千倍，可人类在不少任务上仍更强。更省数据的学习算法、持续从自身行动中学习的系统、多 Agent 互动，都是他希望年轻研究者继续追的方向。这些问题距离成熟产品很远，却很符合前面的 1% 规则。

写在最后

Jeff Dean 给创始人的方法可以从一次小测试开始：拿最强的通用模型跑你的核心任务，记录成功率与失败位置。若它仍几乎做不到，而你手里恰好有独有数据、清楚规格和可重复的评估办法，这个问题就值得继续追。此时先把一轮实验完整跑通，再决定要不要押上未来几年。
