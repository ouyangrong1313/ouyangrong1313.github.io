# Agent的命门是上下文：关键不在少给，而在给对 - 拆解

> 来源：微信公众号「腾讯云开发者」/ 作者 黄照坤 / 发布 2026-08-18
> 原文链接：https://mp.weixin.qq.com/s/PhWGXLaWK0wEpz4Jao09ng
> 获取时间：2026-08-18

## 核心观点

1. **局部输出变短不等于端到端成本下降。** CodeGraph 和 RTK 只有在替代后续搜索、阅读、测试或重复交接时，才可能降低完整任务成本。
2. **工具价值由任务形态与信息存活时间决定。** 图谱适合明确符号的结构定位；若仍需逐点读源码，图查询会成为额外输入并在后续会话累积。
3. **压缩必须带恢复机制。** 终端摘要可能滤掉关键线索，触发补偿性搜索、修改和测试；宽泛搜索、证据核对和验收应可回退原始输出。
4. **跨 Agent 交接应传短 Handoff 与 Artifact 路径。** 完整证据保留在产物目录，摘要只携带当前角色的决策、范围和回源入口。
5. **模型负责判断，程序负责状态迁移和路由。** 自动派发、去重、claim 和计划边界检查等确定性工作应放进状态机/脚本，减少主 Agent 重复搬运历史。

## 7 个分析角度与开头钩子

### 1. 为什么“省 Token 工具”反而可能更贵？
- 一段输出短了，不代表 Agent 因此少走了搜索、修改和测试。
- 成本要沿着信息进入窗口后的行动路径计算，而不是只看工具返回长度。
- 先问工具是否替代后续步骤，再问它压缩了多少字符。

### 2. CodeGraph 什么时候真正有用？
- 已知符号、明确调用面和有限影响范围时，结构图可以替代多轮盲搜。
- 调用链、业务分支和精确行号仍需源码核对，地图不应假装成证据本身。
- 一次探索结果要复用给后续角色，否则每个 Agent 都会重新画同一张地图。

### 3. 为什么 RTK 压缩终端后，任务路径可能更长？
- 被压缩掉的命中可能正是下一步定位问题的路标。
- 少看一行不一定少做一步，补偿性搜索和测试会把节省反向吞掉。
- 关键线索缺失、输出异常或第二次宽搜时，应立即回退原生命令。

### 4. 如何把完整材料与交接消息分开？
- Artifact 保存完整方案、证据和测试结果；Handoff 只传当前阶段要做的结论、约束和路径。
- 交接摘要不是丢事实，而是把长内容从常驻窗口移到可精确回源的存储。
- 下游先按摘要行动，只有出现关键缺口才读取原始产物。

### 5. 为什么状态机比 Main Agent 反复派发更省？
- 每次主 Agent 醒来重读历史、判断阶段、包装报告，本身就是上下文搬运。
- 阶段开始、完成、路由、去重和 claim 交给程序，模型把预算留给方案与审查。
- 自动路由必须保留计划边界和人工叫停，不能把流程推进误认为任务完成。

### 6. 怎样定义“给对”的上下文？
- 只有当前决策需要的信息才进窗口，只有当前负责判断的角色才接收。
- 窗口保留摘要与索引，完整证据按需回源，不让历史永久占位。
- Context density 的分母是实际进入窗口的全部内容，而非模型窗口大小。

### 7. 怎样验证优化是真收益而非偶然波动？
- 对同任务做配对实验，并观察总 Token、时间、失败诊断、测试修复路径和最终质量。
- 对坏案例重复运行，区分稳定问题与模型随机性。
- 白名单只能由端到端证据升级，不能由单次字符压缩或单次账单决定。
