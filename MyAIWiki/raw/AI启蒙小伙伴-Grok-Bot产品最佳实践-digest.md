# Grok Bot 产品最佳实践 - 拆解

## 核心观点
1. 多 Bot 应按职责、记忆和可指认性拆分，而不是堆成全能助手。
2. 注意力清单从实际行为反推优先级，可暴露计划与投入偏差。
3. 例程让 Bot 从被动问答转为在已授权工具范围内主动执行。
4. 研究到 PRD 的关键是并行协作、上下文交接和可核查引用。
5. 人保留战略判断、审批、对外发送和不可逆操作；共享电脑与登录带来账号级风险。

## 七个角度
- 多 Bot 为什么比全能 Bot 可管理？
- 什么是从行为中涌现的注意力清单？
- 例程怎样避免重复操作？
- Bot 如何交接研究、PRD 与设计上下文？
- 引用为什么是 Agent 产出的最低核查接口？
- 共享登录为什么需要账号级治理？
- 人在 Bot 团队中还应保留哪些权力？

## 证据边界
本文为公众号对 Grok Bot 工作坊的转述；内部采用、PR 比例、能力和路线图均未独立核验，不构成安全或效率承诺。
