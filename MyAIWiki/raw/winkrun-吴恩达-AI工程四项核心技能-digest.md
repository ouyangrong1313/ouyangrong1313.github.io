# 吴恩达 AI 工程四项核心技能速查

- 原文：[[winkrun-吴恩达-AI工程四项核心技能]]

## 四项能力

| 能力 | 关键问题 | 可观察产物 |
| --- | --- | --- |
| 构建与部署 AI 应用 | 如何处理非确定输出 | 评估集、错误分类、反馈闭环 |
| 软件工程基本功 | 如何识别架构与运行取舍 | 约束、接口、测试、安全与成本判断 |
| 使用编程智能体 | 如何有效且安全地委派 | 上下文、规格、验证器、权限边界 |
| 塑造构建方向 | 什么值得构建、何时快慢 | 用户问题、MVP、产品规格与取舍记录 |

## 五个核心观点

1. AI 工程是开发者普遍能力，而不只是一个新职位名称。
2. 生成式输出不可预测，评估与错误分析比会调用构件更重要。
3. 基本功没有失效，只是从手写实现转为审查智能体的工程判断。
4. 编程智能体需要心智模型、上下文、验证器与高风险操作边界。
5. 智能体压缩确定性执行后，工程师更应参与问题定义、规格和节奏判断。

## 七个分析角度与开头钩子

### 能力图谱
- “AI 工程能力不是一个新 title，而是一组开发者通用能力。”
- “会用 LLM 只是入口，技能图谱真正从评估开始。”
- “AI 工程师不是孤立工种，所有开发者都在被要求补齐这四项。”

### 评估闭环
- “模型会输出，不等于系统已被治理。”
- “AI 应用最重要的工程资产，可能不是 Prompt，而是错误分析闭环。”
- “非确定性输出不能靠一次演示验收。”

### 工程基本功
- “AI 写得更快，为什么软件工程基本功反而更值钱？”
- “看不见架构取舍的人，也看不见 Agent 正在制造什么债。”
- “基本功从亲手敲代码，变成用工程语言驾驭智能体。”

### Agent 驾驭
- “什么时候该放手，什么时候必须打断 Agent？”
- “没有验证器的自主，只是把风险延后。”
- “上下文、规格和权限边界，比多开几个 Agent 更先要解决。”

### 规格上移
- “当 Agent 会按规格交付，最稀缺的变成规格里该写什么。”
- “工程师不再只接需求，也要参与决定问题是否值得做。”
- “代码生成加速后，判断的瓶颈反而更明显。”

### MVP 节奏
- “什么时候先做 MVP，什么时候必须慢下来？”
- “快不是默认答案，取决于不确定性究竟在用户还是工程。”
- “构建方向包含速度选择，而不仅是功能列表。”

### 分工变化
- “产品定方向、工程做实现的流水线正在被 Agent 改写。”
- “确定性执行减少，不确定性判断增加。”
- “代码更便宜之后，客户理解与权衡不会自动免费。”

## 证据边界

- “一万份职位描述”和专家访谈规模均来自公众号转述，未独立复核。
- 四项能力是讨论框架，不是所有团队、职位和阶段的统一岗位要求。
