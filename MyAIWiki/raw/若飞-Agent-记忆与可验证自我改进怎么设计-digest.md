## 核心观点

1. **生产级 Agent Memory 更像“经验变更系统”而不是“知识存储层”**：Memory 一旦参与工具选择、代码修改、计划和权限申请，就在给历史分配未来影响力。
2. **读取链和写入链必须分开治理**：读取链解决“当前任务要不要用历史、取回哪一版历史”，写入链解决“当前结果凭什么影响未来”。
3. **日志、状态、经验、Skill、Policy 不是一回事**：原始证据、当前状态、候选经验、已验证记忆、Skill/Harness、Policy 至少要按六层资产拆开。
4. **单次成功只能先写成 candidate**：没有复现、对照、外部验证和作用域边界的经验，只适合帮助排障，不适合成为默认规则。
5. **自我改进的核心瓶颈仍然是验证与权限控制**：评估器、评估集、晋升阈值和生产权限必须留在另一个信任域，否则 Agent 只是在学会怎样更快地骗过自己。

## 7 个分析角度

### 1. 为什么“记忆”会从能力变成风险

- 分析：文章一开场就用“调大 timeout 一次奏效，几周后反而毒化下一次修复”的例子提醒，真正危险的不是 Agent 忘了，而是它把偶然有效的处理默认化了。
- 开头钩子：
  1. 不是 Agent 忘得快，而是错经验学得太快。
  2. 一次偶然命中的修复，为什么会变成下一次事故的起点？
  3. 真正危险的不是 AI 没记住，而是它记住了不该默认化的做法。

### 2. 为什么只谈向量库一定不够

- 分析：只做对话摘要 + top-k 检索，只解决“能不能找回”，解决不了“该不该用”“这条经验是不是已经过期”“取回的是不是当前版本”。
- 开头钩子：
  1. 把 Memory 当 top-k 检索，迟早会把过期经验当答案。
  2. 向量库解决召回率，解决不了准入权。
  3. 记忆系统真正难的，不是找回历史，而是阻止错误历史进入当前任务。

### 3. 六层资产为什么是这篇的骨架

- 分析：原始证据、当前状态、候选经验、已验证记忆、Skill/Harness、Policy 六层资产拥有完全不同的更新规则；如果全都塞进 memory 字段，系统就分不清什么是日志、什么是经验、什么是必须遵守的约束。
- 开头钩子：
  1. 最容易把系统做坏的一步，是把日志、经验和规则都叫 memory。
  2. 经验能不能复利，先看资产分层是不是清楚。
  3. 真正的 Agent Memory 不是一张表，而是六套更新规则。

### 4. 为什么单次成功只能先记成 observation / candidate

- 分析：一次 pass 只能说明“当前检查通过”，还不能排除抖动、掩盖根因或误伤性能。文章给出的 candidate sheet 本质是在逼系统承认“原因未确认”，并把 scope、evidence、verifier、expiry、rollback_to 都记清楚。
- 开头钩子：
  1. “测试绿了”为什么还不配叫经验？
  2. 自我改进的第一道门，不是生成候选，而是承认原因未确认。
  3. 没有 scope / evidence / rollback_to 的经验，等于把未来押给一次运气。

### 5. 读取链真正该优化什么

- 分析：MemCon 给出的关键信号不是“检索更多”，而是“需要时再读”；A-TMA 再往前一步，要求系统能区分 active / superseded / transition 等状态，否则“最像成功方案的旧记录”会把当前任务带偏。
- 开头钩子：
  1. 记忆系统最强的能力，可能是不读。
  2. 不是所有历史都该进入当前任务，哪怕它们语义最相似。
  3. 只会 top-k 的 Agent，迟早会被“幽灵记忆”带偏。

### 6. Memory 什么时候才配升级成 Skill 或 Harness

- 分析：记忆进入 Skill / Harness，意味着“参考信息”开始变成“默认行为”。这一步必须比长期记忆更严格，因为它会改提示词、工具协议、控制流、重试和验证路径，而不是只提供建议。
- 开头钩子：
  1. 让 Memory 进 Skill/Harness，等于把参考变成默认。
  2. 真正该锁死的，不是 Agent，而是它碰不到的评估器和权限。
  3. 一个数值偶然奏效，不等于一条流程可以默认化。

### 7. 两条路径 + 一个控制面怎么落地

- 分析：文章最后把体系收成“读取路径 + 写入路径 + 控制面”，并给出证据门、归因门、回归门、权限门、发布门五道门，以及“只记账 → 提候选 → 跑回归 → 低风险自动晋升”四阶段试点路径。
- 开头钩子：
  1. 自我改进不是无限循环，而是五道门后的有限晋升。
  2. 与其讨论 AGI 会不会自我进化，不如先把 CI 失败归类跑成闭环。
  3. 先只记账，再谈自动晋升，才是工程上能活下来的自我改进路线。
