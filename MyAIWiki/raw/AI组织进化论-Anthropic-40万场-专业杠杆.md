# 原始正文

> 上周6月16日，Anthropic官网发布最新一期智能体AI应用研究报告：《Agentic coding and persistent returns to expertise》，可以理解为《智能体编程与专业的持久回报》（文末有链接，需要PDF报告可以私信发送）

这份报告是基于 ClaudeCode 真实使用数据的一手分析：

> Anthropic 对 2025 年 10 月至 2026 年 4 月之间，约 40 万场 Claude Code 交互式会话进行了隐私保护分析，覆盖约 23.5 万名用户，重点研究三个问题：人们到底用 Claude Code 做什么？人和 AI 如何分工？什么样的人更容易成功？

**结论很直接：AI 正在降低编程门槛，但没有降低专业门槛。**

> Agentic Coding 不是简单地把人从代码工作中拿走，而是在重新划分知识工作的边界。会不会写代码，正在变得没那么关键；但你是否真正理解问题，是否能判断结果，是否能把业务规则、技术约束和边界条件讲清楚，反而变得更关键。

## 1. Claude Code 不只是写代码，正在进入完整任务链

（图：The nine modes of work）

如上图，Claude Code 实际用的会话贝分成九类。最大两类仍然是修复问题和构建新东西，分别占 **26% 和 25%**；运行软件占 **17%**；写文档和演示占 **10%**；理解系统和规划变更各占 **7%**；编排 Agent 和流水线、数据分析、测试代码分别占 **3%、3%、2%**。

这说明 Claude Code 已经不是一个简单的"代码补全工具"。它正在进入完整任务链：写代码、修 Bug、部署、配置、跑流程、理解系统、分析数据、生成文档。

更值得注意的是，报告还提到，大多数会话都不是从零开始写代码，而是围绕已有代码库展开：**48% 的会话主要修改已有代码，17% 探索代码，14% 从零创建新代码，还有约五分之一完全不触碰代码库。**

也就是说，Agentic Coding 真正改变的不是"写几行代码"，而是把技术工作从单点任务，推向更完整的工作流。

## 2. 人管方向，AI 管执行

> Anthropic 把决策分成两类：planning decisions 和 execution decisions。前者是决定做什么、采取什么方法、什么算完成；后者是决定改哪些文件、写什么代码、运行什么命令。

结果显示，在典型会话中，**人做出约 70% 的规划决策，而 Claude 做出约 80% 的执行决策。**

这就是报告里最核心的一句话：

> **People decide what to build, and the agent decides how to build it.**

翻译成组织语言，就是：人负责定义问题、设定目标、判断边界；Agent 负责拆解步骤、执行任务、生成结果。

这也解释了为什么 AI 时代真正重要的不是"会不会点工具"，而是能不能把问题说清楚。因为当 AI 越来越会执行，人的价值就更集中在方向、目标、约束和验收标准上。

## 3. "专家"，不是职位高，而是任务理解深

> Anthropic 让模型根据会话内容判断用户在该任务上的专业程度，分为从 novice 到 expert 五级。

Anthropic 不是按照职位判断用户是不是专家，而是看用户在这场任务中表现出来的专业水平。

它看**三个信号**：

- 用户能不能精准表达任务
- 用户知道该让 Claude 验证什么
- 用户能不能发现并纠正 Claude 的错误

报告举了一个很好的例子：一个资深工程师第一次问 Rust 问题，在 Rust 任务上可能仍然是新手；一个从没用过 Python 的会计，如果能清楚说明对账规则，并抓住月末结账的边界条件，在这个任务上就是专家。

**这点很重要。AI 时代的"专家"不是头衔，而是你是否真正理解手上的问题。**

## 4. 越懂业务的人，越能让 Claude 做更多事

从实际的数据结果看，在新手用户的会话中，每次提示大约触发 Claude **5 个动作**，输出约 **600 词**；在专家用户的会话中，每次提示触发约 **12 个动作**，输出约 **3200 词**。

也就是说，专家不是自己干得更多，而是能让 Claude 干得更多。

为什么？因为他们知道该问什么、该检查什么、哪里可能出错、什么结果才算真正完成。一个懂业务的人，不需要自己写每一行代码，但他能把业务规则、边界条件、例外情况和验收标准讲清楚，于是 Agent 就能沿着正确方向跑得更远。

> 核心是：**AI 不是让专业知识不值钱，而是让专业知识拥有了新的杠杆。**
