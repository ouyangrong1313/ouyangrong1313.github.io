## 正文清洗版

作者以 BaoCut 的远程转录功能为例，主张 AI 原生开发没有改变“可行性分析、方案设计、原型设计、编码实现、测试验证”这条基本流程，变化是执行主体：Agent 承担分析、设计、编码与调试；人只在关键节点判断做不做、怎么做、是否做对。

### 可行性分析：先决定要不要做

用户希望将办公电脑上的转录任务交给另一台高算力电脑。作者先判断产品价值和定位，再让 Claude Code 根据项目现状分析技术方案。Agent 列出可选方案，人根据普通用户摩擦、Windows 兼容性与附加 API 能力，选择可直接启动转录服务的方案。

可行性分析仍会误判，但其作用是低成本筛掉错误方向。它至少包含产品价值与技术可行性两层；Agent 提供分析和选项，人保留最终取舍。

### 设计文档：Agent Session 的桥梁

确定方向后，先让 Agent 写包含需求、架构和接口的产品技术设计文档。文档既供人确认和修改，也是有限上下文的 Agent Session 之间传递决策的记忆载体；确认后的文档可直接成为下一次会话的起点，例如“按 docs/remote-transcription.md 实现”。

理想情况下，各阶段都留下需求、设计、原型、代码与测试产物，并用 Git 跟踪变更。复杂项目认真审查设计文档的成本，低于实现后推翻。

### 高精度原型：把需求、交互和 UI 一起确认

传统的 PRD、交互原型和 UI 设计会多次交接。作者主张用 Agent 与 Design Skill 快速生成接近成品的高保真原型，让交互逻辑与视觉设计在编码前被确认。案例中，作者反复调整功能入口、Tab 划分和服务状态显示，最终把高频服务状态从设置页移到主界面。

原型阶段可用自然语言反复修改，人的注意力放在交互、审美与用户直觉；实现后再改则会牵动逻辑、样式、状态管理和测试。

### 实现与自验证：代码不再是主要瓶颈

文档和原型确认后，作者让 Claude Code 按里程碑实现、跑测试、失败后调试并截图确认界面。让 Agent 先在自己的反馈循环中验证，可减少人类介入。作者认为瓶颈转向编码前的设计确认，以及编码后的测试、验证和部署，而非编码本身。

### 测试：以普通用户身份验收

Agent 的测试不能替代用户视角。人应模拟第一次接触功能的普通用户，检查直觉操作、边界输入、错误提示与恢复路径。作者在案例中采用 Agent 自验证加人类黑盒测试，没有逐行 Code Review；但明确这取决于风险，金融等核心逻辑仍可能需要代码审查。

### 三个变化与 Skills 判断

1. 执行从人转为 Agent，人集中于判断与决策。
2. 可行性、技术方案、原型/UI 与测试确认可以合并和简化，但不能省略。
3. 文档从附属品变成协作基础设施，供人审查并跨 Session 传递上下文。

作者认为当模型已能完成大量编码时，Skill 优先级应移到代码两侧：左侧以设计类 Skill 支持原型与确认，右侧以部署、发布和目标推进减少机械工作；优化流程、判断与验证的回报高于默认追加编码 prompt 或 Skill。
