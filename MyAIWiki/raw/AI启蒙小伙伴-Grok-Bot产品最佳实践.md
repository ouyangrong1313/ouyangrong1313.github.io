# Grok Bot 产品最佳实践：用一支 Bot 团队完成研究、PRD、设计与交付

- 原文：https://mp.weixin.qq.com/s/E72_5lA1OfZrvL_oc_ei8g
- 来源：微信公众号「AI 启蒙小伙伴」；作者：邵猛；发布：2026-09-05

## 正文（去噪版）

文章整理 SpaceXAI 产品团队关于 Grok Bot 的工作坊：将 Agent 当作有工具、长期记忆、独立工作能力和即时消息沟通能力的 AI 同事，而不是聊天框中的问答功能。产品动机是聊天框不适合跨职能产出、Agent 需要可验证产出的工作环境、人类无法同时跟进大量 Agent 线程。

团队包括 Chief of Staff、工程经理、工程师、数据分析师、PM、设计师和招聘 Bot。多 Bot 的理由是角色可指认、并行、领域记忆隔离和贴近现实组织；所有 Bot 共享云端电脑的文件与登录，但各自拥有屏幕、记忆、上下文和例程，因此安全边界在账号而非 Bot 级。

关键工作流包括：从真实行为生成“注意力清单”，比对声明优先级与实际投入；将重复操作固化为例程；PM、分析和设计 Bot 并行完成研究、市场数据、PRD 与原型，并要求引用来源；工程经理把 PRD 拆成工单、分派 Cloud Agents，登录或审批时暂停交由人类处理。

人应保留研究结论判断、PRD 战略取舍、代码审查、对外发送、采购和删除等高影响操作。文章的核心不是更强的聊天助手，而是把管理一支团队产品化：PM 从亲手完成工作转向定义目标、配置协作、审核结果。
