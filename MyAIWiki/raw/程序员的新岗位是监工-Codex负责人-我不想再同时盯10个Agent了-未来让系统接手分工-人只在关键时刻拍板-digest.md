## 一句话

多 Agent 的下一步不该让人同时盯更多任务，而应由统一执行系统维护任务状态、上下文和调度顺序，只在目标偏离或高风险动作时请求人类决策。

## 五个要点

1. **注意力才是瓶颈**：同时运行 10-15 个 Agent 会把等待缩短，却把人的上下文切换和通知负担放大。
2. **统一执行系统**：Coding Agent 与通用助手可共享底层 Harness；前台是一个入口，后台可按任务分工多个 Agent。
3. **三项调度状态**：系统至少要管理任务状态、上下文来源和完成标准，避免人承担消息分拣与背景补全。
4. **风险驱动介入**：可撤销、低风险动作自动推进；涉及共享分支、依赖、数据库、密钥、发布、付款或删除的操作再请求批准。
5. **人保留判断权**：人负责目标、边界与最终判断，系统负责并行、重试、汇总和低价值通知的抑制。

## 人类何时应被打断

| 情况 | 默认处理 |
| --- | --- |
| 可继续修复的测试失败 | Agent 继续排查，不立即通知 |
| 需要选择实现方向且会改变目标 | 带选项、证据和影响范围请求决策 |
| 可撤销的本地读/搜/测操作 | 默认执行并留痕 |
| 不可逆或高影响动作 | 暂停，取得明确批准后执行 |

## 五条借鉴

- 为每项并行任务写清“目标、状态、证据、完成标准、下一步”，不要只保存聊天记录。
- 用通知优先级而非任务数量衡量多 Agent 体验；无须人处理的消息应被系统消化。
- 主调度层负责分工和收束，执行 Agent 只回传结论、证据、风险和待批准动作。
- 权限按动作风险分级，默认收紧；不要让“需要人看一眼”变成无意义弹窗。
- 先在一个入口下管理少量边界清晰的任务，再扩大并发，不把窗口数量当成能力指标。
