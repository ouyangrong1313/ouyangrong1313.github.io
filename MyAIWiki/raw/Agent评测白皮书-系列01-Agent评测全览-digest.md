## 核心观点

1. **评测体系不是上线前的一次打分，而是一把持续校准的精密量具。** 它既要判断 Agent 当前好不好，也要指出问题发生在哪一层，并随着真实业务变化更新评测标准与样本。
2. **完整体系由四个模块组成：离线评测、在线评测与监控、Case 挖掘与归因、观测基建。** 离线守住已知，在线发现未知，Case 枢纽负责定位分派，Trace 观测是所有判断的地基。
3. **Agent 演进与评测演进是两条相互咬合的 Loop。** 线上 Bad Case 既可能推动 Prompt、Skill、上下文或模型修复，也可能暴露评测集漏覆盖或 Rubric 判错。
4. **评测资产的核心不是单一分数，而是可回归的样本与标准。** 端到端集回答“事情办成了吗”，过程集回答“中间哪一步坏了”；黄金集、错题集、挑战集分别定义下限、记录已知坑、标定能力边界。
5. **离线回测必须控制变量并接入发布门禁，线上 AB 才是垂直业务 Agent 价值的最终验证。** 多 Trial 取稳定结论，安全与准确性可设一票否决，挑战集要持续拟合线上分布。

## 7 个分析角度

### 1. 它在解决什么管理问题
Agent 项目常见的失败不是模型不会做，而是团队无法可靠回答“现在是否可用、哪里出问题、改动是否真的变好、业务价值如何证明”。评测把感觉决策转成证据决策。

### 2. 它如何定义完整性
四模块、三能力、两条 Loop、一套资产构成全景图：发现问题、定位问题、驱动演进三种能力缺一不可；不要把“有评测集”误当作体系完整。

### 3. 它如何处理长程 Agent
评测对象从最终答案扩展到行为路径与环境状态。Task 应固定输入和成功标准，Rubric 下钻为可回答是/否的检查项，避免“结果看起来不错”掩盖过程错误。

### 4. 它如何分工离线与在线
离线回测是版本变更的门控，负责已知问题的稳定回归；在线影子模式、AB 和巡检面对真实流量，负责未知问题、业务价值与持续稳定性。在线监控则观察运行健康，不等价于质量评测。

### 5. 它如何把异常变成改进
Case 挖掘从反馈、采样、规则和监控等不同来源收集样本；归因沿 Trace 定位根因，再决定进入 Agent 修复 Loop、评测集扩充 Loop，还是 Rubric 校准 Loop。

### 6. 它对工程基础设施的最低要求是什么
冷启动不必先造完备平台，但至少要实现“最小可归因”：保存完整模型输入输出、Skill/Tool 调用和关键环境信息，使一个 Bad Case 能被复现并解释。

### 7. 它给成熟度建设什么节奏建议
全景图是终局而不是起点。冷启动先跑通观测、核心端到端集和基础回测；扩量补齐标准与在线评测；全量运营再推进自动化和规模化。优先补最短的板，而不是平均建设所有模块。

## 开头钩子

### 评测为何是生死线
1. 搭一个 Agent 越来越容易，为什么真正走到全量的项目仍然很少？
2. 如果团队只能靠 Demo 和几个成功案例判断 Agent，扩量时迟早会失去方向。
3. Agent 评测真正要解决的，不是给系统打一个漂亮分数，而是让团队敢于做下一次变更。

### 四模块全景
4. 离线评测守住已知、在线评测发现未知，但两者之间还缺一个把问题送回工程的枢纽。
5. 一张监控看板很齐全，不代表评测体系完备；线上异常能否回到评测集才是关键。
6. 观测、评测、归因和迭代不是四个孤岛，而是一套持续运转的生产系统。

### 两条 Loop
7. 同一个线上 Bad Case，可能改变 Agent，也可能改变评测标准。
8. 评测集越完善，发布门禁越可靠；门禁越可靠，线上新问题越少，这是一个正反馈。
9. 评测体系的终点不是一次通过，而是让 Agent Loop 和评测 Loop 彼此喂养。

### 评测资产
10. 长程 Agent 没有唯一正确答案，评测就不能只做字符串比对。
11. 黄金集、错题集、挑战集分别回答“下限、旧错、边界”三个不同问题。
12. 端到端分数告诉你该不该拉响警报，过程分数告诉你警报响了该找谁。

### 离线与在线
13. 回测分数高不等于线上业务价值高，垂直 Agent 最终要用真实 AB 验证。
14. 没有固定执行环境的回测，最后会让整个团队不再相信离线评测。
15. 安全和数据准确性不能只设置一个平均阈值，应该成为阻断发布的硬门禁。

### Case 与归因
16. “这里出了问题”只是 Bad Case 的起点，真正有价值的是找出为什么出问题。
17. 只修 Agent 不校验 Rubric，可能把系统优化成迎合错误标准的机器。
18. 随机采样命中率最低，却是发现未知风险不可省略的一条通道。

### 落地节奏
19. 冷启动阶段不需要一口气造完美平台，但必须能复现一个 Bad Case。
20. 评测体系的上限由最短的那块板决定，先补短板比平均加码更有效。
21. 全景图的价值不是要求团队照着建设，而是帮助判断现在在哪、下一步补什么。
