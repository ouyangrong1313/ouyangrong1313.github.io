## 一句话总览

Agent 开发不是追逐某个框架或语言，而是为不完全可靠的推理核心建立可证明完成、可恢复、可审计、可接管的执行系统；Harness、身份、状态、浏览器、宿主、Skills 与验证共同构成这层系统。

## 核心观点

1. **代码生产不再是主要稀缺品，可信完成才是。** 一旦 Agent 能写文件、登录系统、部署或扣费，完成不能由模型自述，而要由证据、状态和业务结算判定。
2. **Harness 管全程，而非单次提示。** Context 管每次采样的视野，Loop 管时间轴，Graph 管任务拓扑，Skill 管可加载规程；Harness 持有目标、状态、工具路由、恢复与停止条件。
3. **副作用必须拥有明确责任。** 稳定动作 ID、幂等键、回执、检查点、reconcile、补偿和人工接管，解决了超时或崩溃后“是否已经执行”的不确定性。
4. **入口会分化，任务状态必须合流。** CLI、桌面、IM Gateway 与浏览器各自服务行动、监督、异步触达和跨应用操作，但应投影同一份持久任务、审批与证据。
5. **Agent 能力依赖机器可操作的环境。** 结构化 CLI、稳定 ID、schema、可比较 trace、测试与 artifact，把自然语言猜测压缩为可执行、可验证的接口契约。

## 知识节点速查

| 节点 | 可复用结论 |
| --- | --- |
| 可信完成 | 将概率性推理包在确定性的身份、状态、执行与验证外壳中，完成以证据而非模型表述认定。 |
| 动作回执 | 对真实副作用保留动作身份、幂等键与 receipt；结果不确定时先 reconcile，不能盲目重放。 |
| Harness 边界 | Harness 持有目标与长任务责任，协调 Context、Loop、Graph、Skill、Sandbox 与 verifier。 |
| Goal 契约 | 每个长任务必须写明 outcome、constraints、verifier 与 budget，并有 completed / blocked 等明确终态。 |
| 五类记忆 | 工作状态、事件历史、领域知识、情节偏好、身份隐私分别建模，不能都塞进向量库。 |
| 状态合流 | CLI、GUI、IM 和通知应读取同一任务状态，避免在多入口之间丢失审批、等待与恢复信息。 |
| 浏览器能力平面 | 浏览器同时承载观察、行动、语义、计算、验证与人工接管，必须隔离 profile、身份与不可信网页内容。 |
| Agent-readable surface | JSON Schema、稳定 ID、结构化错误、退出码、artifact manifest 与 trace，让接口同时适合人和 Agent。 |
| Skill 供应链 | Skill 是可变的程序性知识；发现、安装、激活、执行应分权，版本、来源、评测和回滚必须可追溯。 |

## 7 个分析角度与开头钩子

### 1. 从“能写代码”到“可信完成”

生成成本下降会放大分支、工具调用和副作用；工程问题转为谁认定完成、谁承担失败。

- “Agent 写得更快，不代表它能被托付。”
- “一封邮件已经发出但进程崩溃后，重试不是修复，可能是第二次事故。”
- “代码变便宜以后，真正昂贵的是证明结果可信。”

### 2. 为什么 Prompt 不是系统边界

Prompt 仍有作用，但只能解释一次采样；长任务要靠 Harness 管目标、事件、工具、恢复和停止。

- “Prompt 管一次，Harness 管全程。”
- “把更多规则塞进 system prompt，往往只是把工程债伪装成上下文。”
- “Context、Loop、Graph、Skill 不该互相抢概念，它们各自负责不同的状态范围。”

### 3. 副作用与恢复设计

真实行动需要把 dispatch 前后、结果确认和异常状态显式化，未知结果先对账再决定重试或补偿。

- “最危险的 Agent 失败，不是报错，而是不知道它是否已经做完。”
- “幂等键和回执不是支付系统的专利，它们是 Agent 的基本生存工具。”
- “没有恢复路径的自主执行，只是把风险延后交给人。”

### 4. 平台竞争真正争什么

模型公司、Vercel 与 Cloudflare 的项目和收购，指向的是执行、状态、身份、浏览器、部署与可观测性的控制面。

- “模型公司想要的不是多一个 IDE，而是一条可以闭环的执行链。”
- “开源项目看似分散，缺的那一块往往是同一件事：可信执行。”
- “最难复制的不是模型调用，而是生产反馈回路。”

### 5. 多入口为何不能多份状态

CLI 适合行动，桌面适合监督，IM 适合异步中断，浏览器适合跨应用；它们必须共享任务、审批和证据。

- “界面可以有很多，真相只能有一份。”
- “把任务从终端导到桌面，不该等于重新开一个没有历史的会话。”
- “通知不是聊天皮肤，它是长期任务的 attention 与 approval surface。”

### 6. 浏览器为何成为关键边界

浏览器把登录态、隐私数据、不可信网页与真实动作集中在一处；CDP 解决控制，WebMCP 尝试补业务语义。

- “浏览器不是另一个工具调用，它是权限最高、注入风险也最高的能力平面。”
- “能点击不等于理解业务；DOM 自动化之上仍需要语义、身份和审批。”
- “浏览器 Agent 的护城河不是快一点点，而是能否留下完整 action trace。”

### 7. Skills 与工程师学习路径

Skill 将规程变成机器操作包，但其价值来自来源、权限、评测、恢复和组织责任，而不是文件数量。

- “未来的 Skill 不是提示词收藏夹，而是可审计的操作资产。”
- “学 Rust、Go 或 Zig 的目的不是追热点，而是理解运行时、并发、内存与分发的边界。”
- “工程师的价值正从写出更多代码，转向定义约束、组织证据并对结果负责。”
