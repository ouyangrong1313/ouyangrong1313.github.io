## 一句话

Vibe Coding 的长期价值不是多生成代码，而是让 AI 在明确目标、边界和验收条件内完成工程任务。

## 核心观点

1. 开发基本单位从文件和函数转向“有验收条件的工程任务”。
2. 规格说明要同时写目标、边界、实现约束和验收方式。
3. Agent 可靠性来自上下文、工具、状态、权限与反馈闭环。
4. 工程能力没有消失，只是更早进入任务定义和系统审查。
5. 越可拆解、可验证、可回滚的任务，越适合交给 Agent。

## 7 个分析角度与 21 个开头钩子

### 任务入口
- AI 写代码，先要写清任务。
- 需求愿望不是工程任务。
- 验收条件决定交付边界。

### 规格表达
- Prompt 是指令，规格是契约。
- 模糊形容词无法验收。
- 把默认前提变成显式约束。

### Agent 闭环
- 模型加工具不等于 Agent。
- 反馈决定下一步行动。
- 能停下来也是能力。

### 工程判断
- 原型快不代表产品可靠。
- 生成结果不能代替系统审查。
- 遗留系统的规则常藏在事故里。

### 适用边界
- 可验证性是委托尺度。
- 不可逆操作要保留人工闸门。
- 高风险任务先让 Agent 出草案。

### 效率指标
- 代码行数不是交付效率。
- 验证、交付、维护都要计量。
- 更快返工不等于提效。

### 责任重划
- 人定义问题和边界。
- AI 执行明确的多步骤任务。
- 最终交付责任仍在人。

## 5 句金句

- 代码能运行，不代表业务规则正确。
- 模型会写代码只是工程执行的一环。
- 没有验证机制，效率只是更快地产生候选答案。
- 越希望 AI 承担复杂任务，越要先建设上下文和验收机制。
- 代码生成只是环节，工程闭环才是价值。

## 对 Seetong 的 5 个借鉴动作

1. 把告警、配网、设备诊断需求改成“目标—边界—验收”任务卡。
2. 为 iOS、Android、KMP 和 SDK 建立可调用的构建、测试、日志工具。
3. 将权限、隐私、耗电和协议兼容列为不可自动改写的硬约束。
4. 按风险开放动作：读代码和跑测试自动化，发布与数据变更人工审批。
5. 用一次通过率、返工时长、缺陷率和维护成本衡量 AI Coding 收益。
