## 核心观点

1. 对话中心模式在代码任务中尚可成立，是因为仓库、diff、构建和测试可重建工作状态；在可直接编辑的文档、图表和 GUI 产物上，对话会遗漏关键状态。
2. 产物中心协作让可持续演化的产物及其状态成为共同工作现场；对话退回目标表达和判断解释的角色。
3. 选区、批注、人工直接修改和批准是任务上下文，不能只作为 UI 细节或聊天外噪声。
4. Harness 应统一协作协议而非领域模型：维护意图、版本、操作、回执与证据；各产物保留自己的运行时。
5. “完成”必须连到可检查的产物变化和验证证据；不能由 Agent 的完成宣称替代。

## 知识节点（8 个）

- **产物中心**：将持续演化的工作产物及状态作为人机协作的主要现场。
- **对话盲区**：用户在产物上的直接操作会产生未完整进入聊天记录的任务状态。
- **语义选区**：用户选择的元素应携带对象、结构和版本，而非只保存屏幕坐标。
- **版本绑定**：选择、修改、验证与回执必须指向同一产物版本，防止操作过期状态。
- **领域运行时**：浏览器、仓库、构建系统、文档或模拟器各自负责理解、操作和验证所属产物。
- **协作协议**：Harness 统一意图、版本、操作、回执与证据，不强行统一领域内部模型。
- **操作回执**：每次写入需要说明变更对象、结果和可继续工作的状态。
- **验证证据**：产物变化、已验证结果与未确认限制需保留给人判断。

## 七个分析角度与开头钩子

### 对话盲区
- “用户已经在画布上改过了，为什么 Agent 还在复述旧需求？”
- “对话记录完整，不代表工作现场完整。”
- “人开始直接改产物时，聊天框丢掉了什么？”

### 产物中心
- “下一代 Agent 的中心，可能不是更长的聊天记录。”
- “代码、PPT、网页都该成为 Agent 的工作现场。”
- “结果不是对话附件，而是下一轮协作的起点。”

### 语义选区
- “一句‘这里改一下’，如何变成可执行上下文？”
- “截图坐标为什么不足以支撑可靠的 GUI Agent？”
- “让用户点一下，胜过让用户重写一段说明。”

### 版本绑定
- “Agent 改错对象，往往不是模型不懂，而是版本没对上。”
- “选区、修改和验证不指向同一版本，协作就会漂移。”
- “产物中心的第一条工程纪律：每次操作都要有版本。”

### 领域运行时
- “网页要交给浏览器，代码要交给构建系统。”
- “Harness 不该吞掉所有领域模型。”
- “统一协作，不统一每种产物的内部实现。”

### 验证证据
- “Agent 说完成不算完成，证据在哪里？”
- “一个可点击预览，为什么不等于一次已验证交付？”
- “人机协作真正需要记录的，是哪些结果还不能确认。”

### 多元闭环
- “不是所有 Agent 都该长成同一个 Loop。”
- “从单一对话流，到不同产物各自的观察、操作和验证。”
- “Harness 的职责不是替代运行时，而是把闭环接起来。”
