# 2026-07-AI组织进化论-Codex负责人-AI原生工作法（原文摘要）

> **来源**：微信公众号「AI组织进化论」2026-07-21 推送（编译 Peter Yang 访谈 OpenAI Codex 负责人 Alex + 开发者体验负责人 Romain / 原文链接 https://mp.weixin.qq.com/s/5EMMIaXwJm6SL7nYcCoi0g）

## 一句话总结 + 核心金句

> **Codex 团队围绕 Agent 重新设计工作：少写长文档 + AI 参与思考准备 + 多线程管理任务 + 工程师建设环境 + AGENTS.md 是地图 + 招聘看作品**——核心范式转换：从"写代码的地方"变成"管理数字同事的工作台"。

**5 句核心金句**：
1. **"短规格不是少想一点，而是把精力从描述执行步骤，转向澄清意图和验收标准。"**
2. **"Codex 不是更快的答案机器，更像一个随时可以加入讨论、又能立刻下场执行的同事。"**
3. **"开发工具正在从'写代码的地方'，变成'管理一组数字同事的工作台'。"**
4. **"一次失败带来的，不应该只是一次返工，还应该是环境的一次升级。"**
5. **"知识库不是文件仓库。它首先是一套清晰的导航和维护机制。"**

## 核心观点 9 条

1. **十个要点就够了**：Codex 团队很少写长文档，只在问题复杂到无法一人掌握或多人都需要时才写说明
2. **先让 Codex 参与思考，再让它执行**：不一定告诉 Codex 改哪几行，先让它读项目、提选项、问目标用户/优先级
3. **从单线程写代码，转向多线程管理任务**：1 人多个 Agent 并行，工具从"写代码"变成"管理数字同事工作台"
4. **工程师新工作 = 建设环境**：拆可验证环节 + Agent 自查 + 评审 + 迭代；失败应升级环境而非返工
5. **AGENTS.md 是地图不是百科全书**：简短目录 + 知识分层；"知识库不是文件仓库，是导航 + 维护机制"
6. **计划只做两种**：短期 8 周具体 + 长期判断模型能力（不写死中期）
7. **角色边界变模糊但责任不能模糊**：设计师写代码 / PM 做原型；"AI 削弱'这不是我的工作'，不是'这件事没人负责'"
8. **用户是开发系统的一部分**："海盗船"团队 + 开源反馈闭环（自己用→用户用→新用法→产品吸收→再交付）
9. **招聘看"你做过什么"**：主动性 + 作品链接 + "技术从职业边界变成实现想法的公共能力"

## 关键参数 / 决策树

| 维度 | 数字 / 公式 | 备注 |
|------|------------|------|
| 短规格原则 | 复杂项目说明通常**只有 10 个要点** | "短规格不是少想一点" |
| 短期规划 | 最长约 **8 周** | 具体目标集中推进 |
| 长期规划 | 看模型能力可能走到哪里 | **不写死中期**（模型进步太快） |
| Codex 团队迭代闭环 | 团队用 → 用户用 → 新用法 → 产品吸收 → 再交付 | "海盗船"团队节奏 |
| 设计师产出 | 借助 Codex 提交代码已超过半年前 1 名工程师 | 角色流动实证 |
| Agent 失败响应 | 拆可验证 + 自查 + 评审 + 迭代 | "失败应升级环境非返工" |
| 知识组织 | AGENTS.md 目录 + 分层文档（架构/设计/计划/产品原则/质量/安全） | "地图不是百科全书" |

## 4 普通团队可复制原则

| # | 原则 | 操作 |
|---|------|------|
| 1 | 重新定义任务说明 | 少写过程指令，多写目标+背景+约束+验收标准 |
| 2 | 知识变 Agent 可找系统 | 入口+目录+版本+维护责任 |
| 3 | 反馈回路进流程 | AI 不只生成初稿，还能运行检查+评审+修改 |
| 4 | 围绕问题任务而非职能设负责人 | 人可跨专业边界，每项关键工作必须有人作最终判断 |
