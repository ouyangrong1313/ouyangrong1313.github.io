## 正文

我们每天为你更新硅谷最新的 AI 创业与科技播客总结，让你与前沿保持同频。

"我思考的速度比打字快得多。"
"一切都可以编辑、移动和改变。"
"我们能给 agent 的上下文越多，结果越好。"

E Bufar 是 Y Combinator 的设计负责人。这期对话里，她展示了自己最近做的三个项目：用 Paxel 观察人们如何与编码 Agent 协作，用 Sodazine 记录旧金山的城市故事，再用一套新的设计工具为 Startup School 制作视觉资产。

她几乎不再用传统方式从零开始做页面，而是通过说话、整理上下文、快速生成和持续微调，把设计工作变成一条可以反复实验的反馈回路。对设计师、产品经理和工程师来说，最值得关注的不是某个工具的功能，而是设计师开始拥有一种新的工作姿势：把想法说清楚，把上下文准备好，再为自己造出一组随时可以丢弃的工具。

### 设计师先把键盘放下，工作会怎样

E Bufar 说，自己现在几乎只在 Conductor 和 Paper.design 里完成一个项目的端到端工作。寻找视觉灵感时，她会回到 Pinterest，给项目建立一个 mood book，把喜欢的图片和大致的视觉感觉放在一起。

真正改变工作节奏的是输入方式：她发现自己思考的速度快过打字，于是按住功能键，直接把想做的功能用一段连续的想法说出来。Aqua 会把这段语音传给电脑，Agent 再把它落实成页面和交互。

> 设计师的第一步不再是熟练操作工具，而是把脑中的意图尽快外化。

这让设计师可以更早看到结果，也更早发现自己其实没有想清楚的地方。想法可以先保持完整，再让 Agent 帮忙拆成可执行步骤。设计师依旧要判断页面是否正确，只是判断更早发生在成品出现之前。

### Paxel 把编码过程变成可观察的数据

Paxel 的出发点，是 YC 想知道人们究竟怎样使用 coding agents。现在每个人都在摸索自己的技巧：偏爱哪个模型、什么时候提交代码、是否使用 plan mode、Agent 出错时怎么重试。这些行为大多只留在个人电脑里，同行之间很难互相看见。

Paxel 通过终端命令读取 Claude、Codex 和 Cursor 的编码记录，返回一组有趣的个人报告。它借鉴 Spotify Wrapped，把一次次编码 session 变成可以回看的卡片。

> 当设计师开始分析自己的工作记录，经验就从模糊的感觉变成了可以讨论的模式。

未来积累足够多的数据后，Paxel 还会把一个人的习惯与其他 builder 对比。第一版仍是 single-player 模式，因为团队还没有收集足够多的记录。

### 同一套网站，要为人和机器各做一份

在 Paxel 的页面上，E Bufar 特意放了 human 和 machine 两个入口。给人看的版本可以有动效、卡片、悬停反馈和视觉节奏；给 Agent 看的版本则是一份更轻、更容易读取的 Markdown 文件，顶部还会提醒 Agent 不要自动运行页面里的命令。

> 面向 Agent 的界面，核心工作是给它准确的内容，让它快速获得上下文并继续行动。

未来一个产品可能同时拥有面向人的网页和面向机器的内容入口。人仍然保留最后的合并决定，机器则承担从需求到实现之间的大量重复工作。设计师在这里设计的，是人与 Agent 之间的信息通道。

### 当一切可改，设计师就开始造自己的工具

为了做 Paxel，E Bufar 让 Claude Code 实现了 Paper.design 的图像抖动 shader，然后又给自己造了一个小型调参面板。她可以在里面反复调整颗粒感、边缘、旋转和缩放，直到页面拥有想要的质感。这个面板并不需要成为正式产品，完成任务后就可以丢掉。

> 设计师获得的自由，来自可以随时为局部问题造出一件临时工具。

她把这种方式称为 disposable design：为了探索一个问题，临时造一个只服务自己的工具。看到局部不对时，第一反应不再是“留到下一次正式开发”，而是“我可以为自己做一个调节它的工具”。

### 上下文越完整，Agent 越像合作者

做 Sodazine 时，团队把每一次会议都录下来，再把逐字稿放进一个名为 soul.md 的文件。这个文件记录项目的背景、讨论、manifesto 和后续决策，也可以继续拆成 design.md、content.md 等更细层级。它承担的是项目的长期记忆。

> 高质量输出的起点，往往是一份愿意花时间整理的上下文文件。

信息越完整，Agent 越能理解项目真正的气质。作者把 soul.md 当成 exhaustive glossary：会议细节、团队共识、manifesto 里的语气、设计偏好，都可以放进去。重要的不是唯一正确的组织方法，而是先把这些信息捕捉下来，让 Agent 有机会读懂它们。

### 16 个版本的价值，在于快速排除

有了 soul.md，E Bufar 没有直接要求 Agent 交付最终网站，而是先用 Pinterest 建 mood board，再把图片、文章标题和视觉方向一起交给 Claude，让它一次生成 16 个版本。为了浏览这些版本，她又做了一个只给自己使用的 glossary 页面，可以把喜欢的方案置顶，避免在大量探索中丢失线索。

> AI 把第一次尝试的成本压低后，设计师就能把时间放在比较、筛选和组合上。

这样做的好处，是设计师可以在早期同时处理多个方向，不必过早把时间投入到一个还没有被验证的答案上。

### AI 参与越深，人的取舍越重要

Sodazine 里有一个很重要的边界：实体杂志和其中的平面艺术，团队刻意决定不使用 AI。那些作品看上去高度细节化，也能让人感到创作者花了几个月反复打磨。与此同时，围绕杂志建立的网站、地图、文章入口和分享功能，又成为 Agent 很适合参与的部分。

> AI 让设计更快，却没有替设计师决定什么值得被认真对待。

越容易生成，越需要有人为项目设定边界，守住风格，也守住那些不能被自动化抹平的细节。

### 品牌也会进入同一条代码反馈回路

为 Startup School 做视觉资产时，E Bufar 先在 Figma 里手动摆放嘉宾照片，很快发现接下来还会有更多名字和卡片。于是她让 Claude 做了一个自己的模板工具：名单更新后，卡片可以批量生成；文字布局、shader 参数和动效也能在同一个地方调整。为了让社交媒体上的视频首尾无缝，她又做了一个定时录屏工具，保证循环从同一个像素开始和结束。录取通知里的个性化票券也沿用同一套视觉语言。

> 当设计资产进入代码，品牌就获得了可复用、可调参、可持续扩展的结构。

### 写在最后

E Bufar 的方法可以从一个小实验开始：把下一次会议完整记录下来，整理成一份项目上下文；找几张真正喜欢的参考图，让 Agent 基于真实内容生成多个版本；再为最麻烦的局部造一个只服务自己的工具。设计师的价值会越来越多地体现在判断、取舍和想象力上，而这些能力，恰好需要通过一次次具体的尝试被训练出来。
