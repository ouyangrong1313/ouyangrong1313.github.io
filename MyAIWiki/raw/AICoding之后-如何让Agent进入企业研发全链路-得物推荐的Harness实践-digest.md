## 一句话

企业 AI 研发的重点不是让模型多写代码，而是用需求边界、可运行环境、量化验收和经验代码化，将 Agent 接入可持续的 PDCA 迭代飞轮。

## 8 个节点

- **全链路 PDCA**：Agent 覆盖 Plan、Do、Check、Act，避免能力只停留在编码环节。
- **TPRD Contract**：把 PRD 拆为功能点、影响范围、约束、实验和验收，给 Agent 可执行边界。
- **环境护栏**：沙箱/代理/预发环境让修改、运行、日志与验证连续发生，减少等待。
- **UTD 闭环**：用既有与新增单测的执行数据反推修改可靠性，而非只让 AI 生成测试。
- **AI 评测员**：以用户画像和 L1-L5 标准前置评估推荐质量，保留过程供专家抽检。
- **三层知识**：L1 团队硬约束、L2 模块设计、L3 代码注释按作用范围供给上下文。
- **Highway**：已验证的高频问题编码为确定性执行路径，避免每次由模型重新理解。
- **ATV 进化**：长尾问题先由 Agent 探索，人工校验后固化为 Story，回流 Highway。

## 关键证据

| 原文口径 | 含义 |

| 约 52% -> 90%+ | 补齐注释后，AI 回答测试问题的整体准确率变化 |

## 对 Seetong 的借鉴

1. 先为跨端需求补充“影响模块、不可突破约束、验收证据”三项 Contract，再交给 Agent 实施。
2. 将现有测试、日志和设备/服务依赖 Mock 做成 Agent 可连续调用的验证环境，优先消除人工取证等待。
3. 把复发缺陷的排查路径沉淀为可执行脚本或诊断流程；只有确实需要推理的长尾问题才进入开放式探索。
