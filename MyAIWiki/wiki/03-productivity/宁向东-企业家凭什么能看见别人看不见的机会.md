# 宁向东：企业家凭什么能看见别人看不见的机会？

- **原文链接**：https://mp.weixin.qq.com/s/ACo4vidI0MmD6rxZx-am3g
- **原始作者**：宁向东（清华经管学院创新创业与战略系教授，经济学博士）
- **来源**：《宁向东讲公司治理：共生的智慧》，中信出版集团
- **摘编发布**：领教工坊（ClecChina）
- **获取时间**：2026-07-01 09:48 Asia/Shanghai

## 核心结论（一句话）

> **创新型企业家的关键能力不是"敢于冒险"，而是"带着根本问题去观察 + 果断试验"**——克里斯坦森大样本研究证实，4 大行为特征（提问/观察/试验/交际）中，**观察 + 试验**才是显著影响因素，**提问 + 交际**只是必要条件。

## 知识节点（8 个独立概念）

**分类**：个人决策方法论 / 创新者认知方式 / AI 时代产品决策与个人定位

1. **熊彼特-轴心定位**：企业家精神是企业资源集合体中"经久不变、永远重要"的那种资源——"让一切事务运转起来的轴心"。在所有资源（资金/劳动/技术）中，熊彼特唯独把企业家精神放在第一位。
2. **奈特-不确定性-超额利润**：机会可见 → 完全竞争 → 无超额利润；机会不可见 + 被企业家"看到" → 超额利润。"真正的企业家则是在不确定性中看到机会"。
3. **德鲁克-非冒险家**：冒险是表象；真正的企业家清楚自己在做什么、胜算更大，"善于尝试、尝试中学习、风险控制到安全范围"。这与一般人理解的"创新 = 冒险"完全相反。
4. **克里斯坦森-4 行为特征**（vs 管理者对照）：
   - **提问**：主导者问"如何改变现状"（"如果我们这样做，世界会怎样"）/ 管理者问"如何在现状框架内更有效"
   - **观察**：主导者"带着根本问题观察"（无拘束，天马行空）/ 管理者"带着任务观察"（先入为主框架过滤掉好东西）
   - **试验**：主导者把试验视为"创新机会" / 管理者把试验视为"成本项"
   - **交际**：主导者"目的性不强但善于获取新想法" / 管理者"为职业发展和人脉交际"
5. **显著 vs 必要**：定量分析显示，**观察 + 试验**是显著影响因素；**提问 + 交际**是引导成功的重要但非显著因素。**反直觉发现**：大多数人会以为"交际人脉"是企业家最重要的能力，实际不是。
6. **关联性缜密思考**（模式识别）：成功创业家的思考方式"像是直觉，不容易被其他人甚至多数人理解"——本质是"旁征博引式的关联性缜密思考"，让他们"比资深的管理者更快地搜索到问题的有效解决方法"。
7. **舒尔茨-星巴克观察案例**：舒尔茨在意大利旅行期间"在咖啡馆里观察"——不是任务观察，是带着根本问题观察。**结果**：星巴克 = 意式咖啡馆（社区约会场景 + 大量牛奶）+ 美式商业 = 全球连锁。
8. **贝佐斯-亚马逊试验案例**：把试验视为"创新机会"而非"成本项"——在亚马逊通过**组织性安排**推动大家做更多尝试。"尝试越多，产生真正意义的创新的机会就越多"——Prime / AWS / Alexa / Marketplace 都是这一机制的产物。

## 6 个对 Seetong 团队可借鉴动作

1. **每周例会强制提 1 个"改变现状"问题**：Seetong 团队（iOS/Android/SDK）例会默认陷入"如何在现状框架内更有效"（修 bug / 优化性能 / 提测），**强制每周提 1 个"如果我们这样做，世界会怎样"**（如"如果摄像头 SDK 改成事件驱动而不是轮询，4G IPC 弱网体验会怎样"）—— 避免整支团队陷入"管理者陷阱"。
2. **产品经理"带根本问题去现场"**：客服反馈"用户说想要 XXX"≠"用户要 XXX"。产品经理去客户现场前**先列 3 个根本问题**（"用户为什么不用云存 / 为什么不用远程开门 / 为什么 4G IPC 经常掉线"），再观察；**不要带"任务观察"框架**（"我们新功能 XXX 用户怎么看"），避免被先入为主过滤掉。
3. **每月"试验配额"机制**：iOS/Android/SDK 小组每月允许 1-2 个"打破常规的小试验"（如"这次不用 BaseVC 写新页面，试试 SwiftUI / Kuikly" / "这次不加完整埋点，先跑个 AI 推荐的简化版"）—— 把试验从"成本项"重新定义为"创新机会"。
4. **跨领域"想法火花"午餐会**：每月 1 次工程师 / PM / 客服 / 测试混合午餐会。**明确规则**："目的不是人脉，是想法火花"—— 不许讲项目进度，只许讲"最近看到的一个有意思的东西 / 想到的一个怪问题"。对应克里斯坦森"主导者交际目的性不强"特征。
5. **主人月报增加"上月最关键的 1 个观察 + 1 个试验"复盘**：主人作为 Seetong 团队的"主导者角色"，每月问自己"上月哪个观察改变了我的判断 / 哪个试验产出了新认知"—— 与 channel memory 6/30 已开始的"AI 进步观察"笔记机制接续。
6. **警惕"任务观察"陷阱**：客服反馈"用户说"是"任务观察"产物——是带预设框架的观察。**Seetong 客户成功需要"根本问题观察"**：不是"用户报了什么 bug"，而是"用户为什么在这个时候报这个 bug / 他当时想完成什么任务 / 我们的产品在哪一步让他卡住了"。
