知识节点（9 个独立概念）

  • 公司 OS（Operating System）：把 1% AI 高手的操作沉淀成全公司都能调用的技能；已进入团队分工、招聘标准、PM 交付判断
  • 1% vs 90-99% 鸿沟：1% 高度 AI 化用户 + 90-99% 不知道什么时候该用什么——公司 OS 让 1% 经验不锁在个人电脑里
  • 工作地图（work map）：GitHub 风格按职能拆分（customer success/data science/design/engineering/finance/legal/marketing）；每个部门标”哪些活希望人多花时间 + 哪些活应该交给自动化”
  • 从烦人重复动作开始：”公司 OS 不一定一开始就是 OS，它从第一个自动化的小工作流开始”；第一块砖 = 不再漏信息的表单（如 ask-product 频道的 Slack automation）
  • 50 页 playbook 拆 skill：Dust agent builder 把 playbook 拆成可执行动作；GTM agent 路由；playbook 从静态文档变成可执行动作
  • Slack/邮箱入口：”换界面的摩擦会杀死习惯”——演示惊艳，月底没人打开；按钮/表单/agent 调度必须放在员工已经停留的地方
  • AI Ops = 新的 Biz Ops：”当你说它是每个人的责任，它最后就成了没有人的责任”——必须设 AI Ops 专职岗位，强好奇心+愿试最新工具+对效率改造执着
  • Captain model 精简 PM：5 个 PM + 4 个设计师；每 feature 1 个 captain；不固定属于某个职能——谁解决最难部分谁担任
  • AI 成熟度 4 级招聘：1) 聊天 2) 自动化一个工作流 3) 给自己搭 app 4) 做 shared app ship 给客户；screen share 60 秒看出对方停在哪一级

正文要点（6 条）

  1. 公司 OS 是组织管理升级：1 个 AI 高手 → 全公司都能调用；已进入团队分工、招聘标准、PM 交付判断
  2. 1% vs 90-99% 鸿沟：公司 1% 高度 AI 化 + 90-99% 不知道用什么；OS 让 1% 经验变 99% 都能用
  3. 从第一个烦人重复动作开始：Slack automation / Claude / Dust 解决”PM 来回追问”——第一块砖 = 不再漏信息的表单
  4. playbook → skill：50 页 PDF 没人会照着做；拆成 Dust agent + GTM agent 路由 = 可执行动作
  5. 入口必须留 Slack/邮箱：”换界面的摩擦会杀死习惯”——按钮/表单/agent 调度必须放在员工已停留的地方
  6. PM 101 反而更硬：AI leadership 课程每月都在变，PM 101 底层原则稳定得多；速度变快后 PM 更需守住慢功夫

6 个对 Seetong 团队可借鉴动作

  1. Seetong 工作地图体检：现在各团队（iOS 研发/后台/客服/产品）有没有标”哪些活希望人多花时间 + 哪些活应该交给自动化”？先用 GitHub 风格目录画出 7 个部门的工作地图
  2. 从 1 个最烦人的重复动作开始：Seetong 找 1 个反复做又厌烦的动作（工单分诊/反馈归类/工时记录/工时填写），先用 Slack automation / Claude / Codex 跑起来——第一块砖 = 不再漏信息的表单
  3. TAPD SOP 拆成 Codex/Claude skill：Seetong TAPD SOP / 客服 SOP / 排班规则 → 拆成 Codex skill；让新人不用从零认识团队约定
  4. 入口留在 Slack/飞书：不要让 Seetong 团队去新界面找 agent；AI 入口在现有协作工具里——飞书/Lark/钉钉/企业微信都已能接 Bot
  5. AI Ops 专职岗位：Seetong 是否需要 1 个 AI Ops 专职岗位？“每个人都有责任 = 没有人的责任”——参考 Laurel 路径：1 个 Sasha 证明效果 → 每个部门要自己的 AI Ops
  6. AI 成熟度 4 级招聘：Seetong 招聘技术岗让候选人 screen share 现场展示怎么用 AI；分 4 级：1) 聊天 2) 自动化工作流 3) 给自己搭 app 4) 做 shared app；简历”AI pilled”易写，60 秒就能看出真假
