# 麦肯锡：Agent 也需要绩效管理、责任归属与退出机制

- 原文链接：https://mp.weixin.qq.com/s/Mk23TRE8nsHfmkESuFaxBQ
- 来源：微信公众号「AI组织进化论」；对 McKinsey Talks Talent 2026-08-26 对话的整理
- 获取时间：2026-09-03

## 核心结论（一句话）

当 Agent 开始承担核心工作，组织应把它视为需要业务 Owner、可度量绩效、技术护栏、生命周期与退出机制的数字劳动力；工具使用率不能替代对工作重构、价值、成本、风险和人的认知负荷的管理。

## 知识节点

- **数字劳动力盘点**：企业应像盘点岗位与人才一样，明确已部署 Agent 的数量、任务、协作岗位、成本、风险和实际产出。
- **业务绩效Owner**：使用 Agent 的业务负责人拥有业务结果和绩效责任，不能把结果责任完全转交给 IT、CTO 或 AI CoE。
- **技术治理护栏**：IT/AI 团队负责平台、技术标准、权限、风险护栏和生命周期能力，为业务团队承担结果提供稳定底座。
- **Agent-KPI**：Agent 的评价必须连接任务准确率、异常率、人工交接、质量、周期、调用成本和业务价值，而不仅是账号数或使用频次。
- **生命周期管理**：Agent 随模型、数据、权限和业务流程变化而失效，需要配置、训练、复核、优化、停用和替换机制。
- **认知负荷**：AI 取代重复任务后，人可能更密集地处理判断、复杂决策和困难对话，组织要将认知与情绪成本纳入工作设计。
- **Humanware**：组织绩效来自人类能力、数字劳动力和工作流共同构成的工作系统，而不是单独采购硬件、软件或模型。

## 正文要点

1. **管理对象改变**：讨论重心从“员工会不会用 AI”转到“组织怎样管理 Human + Agent 的混合劳动力”。采购、培训和使用率属于早期采用信号，不能回答责任、成本和价值问题。
2. **责任应按结果和底座分层**：财务 Agent 的绩效归财务负责人，技术团队负责可用平台、统一标准、风险治理与生命周期。业务拥有结果，技术提供底座，治理守住边界。
3. **绩效必须落到工作**：账号数、活跃度和培训人数不说明 Agent 完成了什么。应观察任务是否被重构、人工交接是否减少、周期和质量是否改变，以及收益能否覆盖运行成本与风险。
4. **内部专家是转型关键资产**：理解客户、规则、历史和异常的业务专家，能为 Agent 提供任务边界与质量判断。培养“业务专家 + AI”往往比脱离领域的通用技术扩张更接近工作流重构。
5. **自动化可能提高人的认知负荷**：剩余工作更偏判断、问题解决与困难沟通，管理者不能只把节省工时算作净收益，还要调整工作节奏、管理幅度和恢复空间。
6. **HR 的对象扩展为工作系统**：人力与组织职能不再只处理岗位和人才，也需要参与定义哪些工作交给 Agent、人的责任边界、Agent 配置与混合团队的绩效标准。
