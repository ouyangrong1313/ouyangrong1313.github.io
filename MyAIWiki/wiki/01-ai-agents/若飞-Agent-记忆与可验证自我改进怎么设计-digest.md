## 一句话总结

**这篇文章真正要解决的不是“Agent 怎么记得更多”，而是“哪段过去何时、以哪一版、在什么作用域里、经过哪些闸门，才配影响未来默认行为”**。若飞把 Agent Memory 压成了一个可治理的工程面：**读取链 + 写入链 + 六层资产 + 五道门 + 四阶段试点**。

## 8 节点速查

1. **经验变更系统**：Memory 负责给历史分配未来影响力，而不是只做存档
2. **读取链**：先判断当前步骤要不要读历史，再判断取回哪一版
3. **写入链**：单次成功先记 observation / candidate，不直接默认化
4. **六层资产**：原始证据 / 当前状态 / 候选经验 / 已验证记忆 / Skill-Harness / Policy
5. **候选经验晋升单**：claim / scope / evidence / verifier / rollback_to 结构化记录
6. **状态感知检索**：active / superseded / transition 比相似度更重要
7. **五道门**：证据门 / 归因门 / 回归门 / 权限门 / 发布门
8. **四阶段试点**：只记账 → 提候选 → 候选跑回归 → 低风险自动晋升

## 5 道门（最值得抄回工程里的那张表）

| 门 | 通过条件 | 不通过时 |
|---|---|---|
| 证据门 | 日志、Diff、环境、版本齐全 | 只留事件，不生成经验 |
| 归因门 | 结果可复现，有对照和反例检查 | 保持候选状态 |
| 回归门 | 目标集改善，保留集无明显退化 | 拒绝晋升 |
| 权限门 | 未扩大权限和副作用范围 | 转人工审查 |
| 发布门 | 影子或灰度指标稳定，可快速回滚 | 回退上一版 |

## 4 阶段落地路径

1. **只记账**：先把任务、工具调用、Diff、测试、退出码、状态和 Harness 版本记清楚
2. **提候选**：Agent 允许聚类重复失败、提出候选记忆和规则修改，但不自动生效
3. **候选跑回归**：固定目标集、保留集和干净环境，先报告收益 / 退化 / 成本
4. **低风险自动晋升**：只开放输入稳定、验证明确、权限窄、失败易撤回的规则

## 5 个关键判断

- **记忆不是资料袋，是经验变更系统**
- **单次 success 只能先算 candidate**
- **检索层最强的能力，可能是不读**
- **Memory 进 Skill / Harness，等于把“参考”变成“默认”**
- **真正不能交给 Agent 改的，是评估器、阈值、预算和生产权限**

## 对 Seetong 团队可直接借鉴的 6 个动作

1. **按六层资产改造当前故障记忆**：日志、状态、候选、验证后经验、自动化流程、权限规则分开存
2. **补候选经验晋升单**：任何“修复成功”都要记录 scope / evidence / verifier / rollback_to
3. **检索前做 need-memory 判定**：当前步骤到底该 retrieve、re-retrieve，还是 no-op
4. **把评估器和生产权限放到 Agent 外**：候选 Harness 不得改 verifier、阈值、凭证、预算
5. **从 CI 失败归类开始试点**：输入稳定、验证便宜、副作用小，最适合跑第一遍闭环
6. **给记忆补 status / supersedes / evidence_ref**：把失效关系和回滚链做出来
