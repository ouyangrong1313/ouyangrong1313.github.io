Graph Engineering：从 0 到 1 小白完整教程（速读摘要）

一句话：Graph Engineering = 把“我希望一个 AI 自己搞定”改成“我告诉一群 AI 怎么分工、怎么交接、怎么验证、怎么停止”；Loop 没死，它只是 Graph 里的自环节点。

8 节点速查表

节点 一句话定义
Graph是Loop上层结构 Loop 是自环，Graph 是多个循环和节点的协作系统
Graph准入阈值 多角色、条件分支、并行、三轮不收敛才值得上 Graph
节点存在性检验 只有模型/工具/角色/验证责任真的不同，节点才应独立
共享状态契约 定义字段、类型和写权限，避免错误沿边污染下游
路由代码化 条件明确的路由用代码，AI 只处理模糊判断
独立审阅节点 审阅要换模型、上下文或证据源，防止同源 AI 互相点头
写权限收口 多 AI 可并行读和提意见，同一时间只让一个执行者改东西
小Graph串联 复杂任务拆成一串小 Graph，而不是做一个超级图

Graph 准入四问

  1. 是否需要两个以上明确角色？
  2. 是否存在条件分支？
  3. 是否有可以并行推进的独立子任务？
  4. 单 Loop 是否三轮仍不能稳定收敛？

命中两项以上，上 Graph；只命中一项，先补强 Loop 的验收标准、停止条件和验证器。

4 个最该抄回工程的规则

  • 节点要为存在辩护：能合并就合并，别把一个简单任务拆成一堆装饰节点。
  • 状态先于执行：开始跑之前先定义状态结构、读写权限和检查点。
  • 路由尽量确定：能 if/else 的别交给 AI，自由判断越多越难复现。
  • 审阅必须独立：换底座、换上下文、锚定测试/编译/事实来源。

5 个坑

  1. 为了图而图：一个 Loop 就能做的事被拆成五个节点。
  2. 状态不定义：节点之间传什么全靠默契。
  3. 路由全交给 AI：同一输入两次跑出两条路线。
  4. 审阅和执行同源：AI 对自己的输出过于宽容。
  5. 没有预算上限：并行节点和重试会快速烧 token。

5 个借鉴动作

  1. 在 MyAIWiki 编译流程里，把“raw -> digest -> wiki -> index/log -> 校验”画成固定 Graph。
  2. 给每个编译节点定义状态字段：来源元数据、核心观点、知识节点、内链、校验结果。
  3. 把“内链查找”和“反事实审阅”做成独立审阅节点。
  4. 写入文件仍由单一执行者完成，避免多个 Agent 同时改索引。
  5. 对每个 Graph 设重试上限和停止条件：抓取失败、内容不足、索引冲突、校验不通过都要明确收口。
