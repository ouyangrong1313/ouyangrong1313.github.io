# Agent能力不足维护代码库 — 速读摘要

## 一句话总结
HumanLayer 创始人用 SlopCodeBench 实证：最优 Agent 在分阶段迭代评测中仅通过 16.3% 检查点，"无人值守软件工厂"在复杂长期项目中尚未成立。

## 速查表

| 核心观点 | 关键数字 / 案例 |
|---|---|
| "关灯软件工厂"小任务可行，复杂系统不可持续 | 架构退化成本按月/年计 |
| 测试通过 ≠ 可维护 | Agent 三处补判断，测试全过，下次改规则得同步改三处 |
| SlopCodeBench 分阶段评测 | 36 任务、196 检查点，最优通过率 14.8%→16.3% |
| 先规划再动手 | 20-30 分钟规划省掉数小时审查返工 |

## 反直觉点
- Agent 写代码越快，人工审查的瓶颈越突出；但把审查也交给 Agent，反而加速架构退化。
- "一次跑通"和"连续几轮还能改得动"完全是两回事——当前所有主流评测都只测前者。

## 对 Seetong 可借鉴动作
1. 大改动（多模块联动）提 MR 前先写 200 字改动方案，负责人确认后再让 Agent 铺开实现。
2. 给 Agent 加模拟器截图或真机录屏能力，不要只靠单元测试判定交付。
3. Agent 参与的每次改动，把规划对话和否决方案写入项目记忆，避免接手时重复踩坑。
