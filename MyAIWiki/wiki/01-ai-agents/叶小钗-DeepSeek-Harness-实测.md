# DeepSeek Harness 实测：从插件运行时到消息调度

- 原文链接：https://mp.weixin.qq.com/s/gB9FgNZTvNpPG6PtiEDudw
- 来源：微信公众号「叶小钗」；作者：叶小钗
- 发布时间：2026-08-18 09:00 CST；获取时间：2026-08-18

## 核心结论（一句话）

> DeepSeek Harness 将模型、工具、文件系统、会话与 agent loop 装配为由服务依赖驱动的插件树；其工程价值在于把能力替换、消息时机、会话重建与工具治理放到可见的运行时契约中，而不是把它们分散进各个工具或模型调用。

## 分类提炼

- 场景：Agent Runtime、插件化 Harness、消息调度、会话恢复、工具策略
- 类型：公众号技术拆解 / 单任务体验对比

## 知识节点（8 个独立概念）

- **插件树**：Bundle、Profile 和 Loader 将模型、工具、会话与 loop 组合成按依赖激活的运行时。
- **服务依赖**：插件声明所需与提供的能力；依赖出现、替换或消失会决定其激活与清理。
- **能力接缝**：Service Definition、Provider 与 Consumer 三方约束，使环境差异不泄漏到上层工具。
- **Step-Turn**：step 表示一次模型请求加工具调用，turn 表示完成一项任务所需的完整执行回合。
- **消息调度**：`followup`、`steer`、`inject` 由发送方标记新任务、当前回合补充和后台上下文注入。
- **会话重建**：模型历史从追加 Session 日志派生，投影和缓存是可丢弃的重建层。
- **单调守卫**：工具策略的拒绝不可被后续宽松插件推翻，防止策略链意外扩大权限。
- **可复现评测**：Agent 对比必须公开任务、环境、轨迹、成本口径与验收，否则只是一轮观察。

## 可组合运行时

本文的架构重点不是给某个工具增加插件接口，而是让模型接入、文件系统、沙箱、日志、工具和 agent loop 共享同一种生命周期与服务依赖模型。Web UI 和 headless 命令行可进入同一核心；入口变化不应迫使模型或文件系统实现改变。

能力接缝为替换保留边界：文件工具调用稳定的 `ctx.fs` 接口，Provider 自行负责本地路径、受限沙箱或远程文件系统的差异。这个思路可推广到模型和会话能力，但稳定接口只能减少耦合，不能自行保证替换实现的语义或性能一致。

## 任务推进与会话事实

消息队列的关键不是按文本判断用户意图，而是使发送方明确调度时机。`steer()` 用于在下一个 step 影响正在运行的任务，`followup()` 则排在当前 turn 结束后。这样 UI、后台插件和主循环之间的“什么时候处理”成为协议的一部分。

Session 采用追加日志，记录用户消息、模型回复、工具结果和请求构成。当前对话、缓存和压缩内容从日志投影而来，因而可以用于恢复、回放和分支。压缩后的替代上下文不应冒充或覆盖原始事实；空 assistant 输出也可以保留为用量记录，同时排除在后续对话历史外。

## 工具策略与评测边界

工具调用进入具体实现前应经过统一策略和审批管线，并在结果后统一执行超时、重试、后处理、事件通知与日志记录。文中描述的单调守卫适合安全关键的拒绝规则：一旦拒绝形成，后续插件只可继续拒绝或弃权。具体文件或 Shell 限制仍应由各能力 Provider 负责。

作者对同一慢接口任务的试用称 Codex 约 9 分钟完成聚合接口改造，DSH 中的 V4 Flash 约 20 分钟降低若干接口耗时，V4 Pro 两轮后未产生可观察改动。这些数字缺少代码、执行轨迹、环境控制、模型参数与验收协议，只能记录为作者体验，不能据此判断通用能力或成本优劣。实际选型应以固定任务集、独立复跑和可审计轨迹验证。

## 采用边界

- 把服务契约和日志重建作为设计参考，但先验证当前版本 API、生命周期语义与迁移成本。
- 将“何时接收消息”列入 Agent 协议；不要仅依赖模型对补充消息的语义猜测。
- 工具策略采用默认拒绝、明确审批和不可撤销的拒绝规则；并对具体 Provider 再做资源和权限限制。
- DeepSeek Harness 处于 developer preview 的表述来自原文；进入生产前须独立确认兼容性、维护承诺和运行稳定性。
