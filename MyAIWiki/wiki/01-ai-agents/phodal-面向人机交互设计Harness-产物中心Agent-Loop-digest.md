# 产物中心 Agent Loop - Digest

## 一句话

对话不再是唯一中心后，Harness 的职责是把人和 Agent 对同一产物的意图、版本、操作、回执和验证证据接成闭环。

## 速查表

| 层面 | 产物中心要求 |
| --- | --- |
| 上下文 | 聊天记录之外，选区、批注和人工编辑也是状态 |
| 定位 | 操作绑定语义对象和版本，不依赖截图坐标 |
| 执行 | 各领域运行时负责自己的结构和操作 |
| 回执 | 每次变更可定位、可比较、可继续 |
| 验证 | 保存已验证结果和未知限制，不用“完成”代替证据 |

## 三个反直觉点

1. Canvas 的关键价值不是视觉预览，而是让对象和局部反馈成为下一轮输入。
2. Harness 不该统一所有产物模型，只需统一协作协议。
3. 产物中心并非去掉对话，而是取消对话对状态的垄断。

## 证据边界

这是产品与架构方向文章，未独立复现其中提到的 Codex、Cursor、Qoder 或 Better Harness 实现；采用前应以真实任务验证版本绑定、回执与领域验证是否改善交付。
