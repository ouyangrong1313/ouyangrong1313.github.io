# DeepSeek Super-Agent - 速读

## 结论

单 Session 串行慢且污染，多 Session 互不通气；拆成常驻 Router（管全局、不干活）+ 隔离 Worker（挂完整工具、只汇报），再让环境事件而非 Prompt 来驱动。

## 速查表

| 层 | 解决什么 | 关键设计 |
|---|---|---|
| Router | 全局连续性 | 不配 Bash；积压自动合批，6.4 秒 → 1.6 秒 |
| 事件引擎 | 主动性与信噪比 | 两级过滤、订阅直通、Inline & Spill、投机执行 |
| 在线运行 | 与人打交道 + 不崩 | 异步双工 ReAct、存算分离、外部 Watchdog |

**四组硬数据**：直通路由省 30% 决策次数、37% 读缓存 Token；p95 完成时间 15.7 分钟 vs 29.5 分钟；人类并发上限 3~5 个 Session。

## 反直觉点

- **Router 越弱越好**：不给它执行工具不是省成本，是保证它不会成为瓶颈也不会误用工具。能力边界比模型选择更本质。
- **积压是优势**：常规系统消息越多越慢，这里合批后单次决策更便宜。前提是决策无状态、可推迟。
- **空转比崩溃更贵**：Watchdog 用模型判断 Worker「有没有实质进展」，把最隐蔽的故障显性化。进程活着不等于在干活。
- **上下文靠引用不靠灌入**：超长内容溢出到窗外只留 ID，需要时顺引用图一跳一跳取。

## 对 Seetong 可借鉴动作

- 巡检只做发现与分派，深挖另起隔离上下文，避免一次排查污染整条链路
- 长任务的成功判据加「内容是否实质推进」，防止写出空壳报告也算成功
- 上百条反馈聚成批一次判断，成本随积压下降
- 新反馈进来先自动尝试复现定位，有结论再叫人
- Logan / TAPD / 反馈之间用 ID 串联按需取，别一次性全塞进 prompt
