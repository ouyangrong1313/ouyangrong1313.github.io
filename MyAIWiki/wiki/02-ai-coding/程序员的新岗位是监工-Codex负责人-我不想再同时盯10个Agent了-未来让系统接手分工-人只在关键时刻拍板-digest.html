程序员的新岗位是监工：Codex负责人谈多Agent调度与关键审批 - 速读

多 Agent 的体验指标不该是同时开了多少窗口，而是系统是否把低价值通知、任务分工和上下文维护消化掉，让人只处理真正需要判断的节点。

  • 注意力调度：并行提速不等于工作更快；通知的时机与优先级是核心体验。
  • 任务三态：调度层必须知道每项任务的状态、上下文来源和完成标准。
  • 主调度层：后台执行者可分工，前台只呈现目标、结论、证据、风险和待审批动作。
  • 风险驱动审批：可撤销的读/搜/测默认执行；生产、凭据、数据删除和难回滚动作必须等人批准。
  • 人类最终判断：人定义目标、边界和验收，不应成为多个 Agent 的消息分拣员。

最小实践：先把并行任务统一成“目标 + 状态 + 证据 + 下一步 + 风险”卡片；再逐步让系统抑制可自行恢复的通知，并将批准门禁收敛到高影响操作。
