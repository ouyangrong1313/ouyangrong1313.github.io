# 工厂工程师,不是产品工程师 - Digest

## 一句话总结

> **"工程师的活,从造车变成了造工厂"** — Warp 创始人 Zach Lloyd 宣布团队从"产品工程师"升级为"工厂工程师";**成功 = 工厂效率 ≈ 出货产品 / (推理成本 + 人的时间成本)**;**人在环里 = 需要复盘的失败**;8 步流水线 + **递归自我改进** = 黄金路径。深思圈主编反对无脑造工厂,主张**看任务分工** — 工厂自动化"怎么做",人攥"做什么"和"为什么"。

## 速查表(8 节点 + 8 步流水线 + 公式)

**8 节点**:工厂工程师思维(造车→造工厂)/ COGS 重定义(研发开支→可变成本)/ 人在环里=失败(人在分母里被压)/ 8 步流水线(分诊→spec→实现→review→验证→CI/CD→监控)/ 递归自我改进(每次人介入→优化→下次不必)/ Bakaus vs Lloyd 两极(人留 20% vs 人在环里失败)/ 做什么 vs 怎么做(深思圈中间路线)/ 1300 待办反思(不该做>做不出来)

**8 步流水线 + 公式**:
```
分诊 → spec → 实现 → review → 验证(computer-use)→ 人审 → CI/CD → 监控(闭环)
工厂效率 ≈ 出货产品 / (推理成本 + 人的时间成本)
```

**金句**:"给所有工程师无限 token 预算的日子结束了" / "人在环里 = 需要复盘的失败" / "我们不做,别人会做" / "无脑地、更快地造更多,从来不是战略"

## 同月两极对比 + 深思圈反转

| 创始人 | 立场 | 关键句 | 卖什么 |
|---|---|---|---|
| Paul Bakaus(设计工具) | 人在环里是重点 | "别把人推出循环,人留最后 20%" | 品味工具 |
| Zach Lloyd(Warp) | 人在环里 = 失败 | "每用一次人在环里的 agent,都要当复盘的失败" | 工厂平台 Oz |

**深思圈反转**:两人都卖自己的东西(屁股扣掉),真相是**看任务**:
- **能被机器校验对错的活(怎么做)** → 工厂,Lloyd 对
- **靠判断定生死的活(做什么)** → 留人,Bakaus 对
- 工厂自动化"怎么做",**人依然攥"做什么"和"为什么"**

## 最反直觉 + 5 个 Seetong 借鉴

**最反直觉**:**自动化"怎么做"越彻底,整盘棋越押在"什么才值得做"上。** 1300 待办的真正问题不是"谁来实现" — 是"哪些根本不该做"。Lloyd 把"怎么做"说透,对"做什么"出奇安静 — 那才是工厂关不掉的唯一工序。

**5 个 Seetong 借鉴**:
1. **COGS 视角体检** — AI Coding 投入产出比作为最高级指标
2. **1300 待办反思** — 先盘"不该做"再谈"谁能做"
3. **做什么 vs 怎么做的边界** — "怎么做"工厂化,"做什么"留给人
4. **递归自我改进雏形** — 跑分失败→沉淀 Skill 约束→下次自动跑(对照 [[02-ai-coding/面向Skills编程-淘宝企业购端到端研发提效实践]] ADJUSTMENT_PLAN)
5. **人在环里 = 失败的纪律** — 经常介入同一类问题,优先补 Skill 约束,不是继续"复盘"
