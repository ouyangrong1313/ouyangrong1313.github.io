# Capihom-Lenny-Andrew-OpenAI-Codex-产品工作新形态

- **嘉宾**：Andrew Ambrosino（OpenAI Codex app product and engineering lead）

## 核心结论（一句话）

实现变便宜后，产品工作的稀缺资源从"工程实现"转向"品味 + 调度能力"——Codex 周活 500 万 / OpenAI 内部 100% 员工用 / 产品流程从 90 份文档倒过来成 90 个原型。

## 知识节点（8 个独立概念）

1. **产品流程倒过来**：过去"先文档后工程"是防风险长链条；Codex 把工程打便宜 → 一个新功能可能同时出现 90 个没有协调的实现尝试，难题从"谁来写代码"转向"哪部分值得保留"
2. **品味 = 调度能力**：不是配色和动效（Paul Graham 穿工装短裤也有 strong taste），而是 90 个尝试里选方向、合并片段、决定主功能——"如果什么都能做，目标是什么，我们怎么到达那里"
3. **选对表达媒介**：PRD、原型、artifact 是不同阶段的工具；AI 把媒介和阶段拆开了——"漂亮原型"不等于"可发布"，可能是等下一代模型的 artifact
4. **baby version 代码库**：很多公司有简化版 Cursor / 简化版 Codex 的轻量产品，团队在里面快速试 sidebar/pane/group chat 交互；它是设计流程的一部分 ≠ 正式工程排期
5. **PM 不能取消**：Andrew 明确反对"所有人都叫 builder"——"这是很糟糕的想法"；产品/设计/工程各自有可学习最佳实践，PM 工作像"区域防守"——找空白区、把信号引到产品形态
6. **Codex = home base**：不重做 Excel / Premiere，AI 补接口；Codex 给自己写扩展改 Premiere marker；"专业工具继续存在，AI 补一层接口"
7. **别和流程绑定，要和结果绑定**：去年 11 月能规划的东西过几个月就不一定；2 月发布的 Codex app 若 11 月准备好结果完全不同——"保存好想法等模型跳一下"
8. **Codex 周活 500 万**：1 月以来使用量增长 6 倍 / 周活用户超 500 万 / OpenAI 内部近 100% 员工用 / 范围越过工程团队（含市场/PR/财务/法务）

## 6 个对 Seetong 团队可借鉴动作

1. **Seetong AI Coding 现状体检**：识别哪些功能走"90 份文档"长链、哪些可走"90 个原型"短链；V8.3.13.X 的 13 条 P0 stories 哪些适合直接给 Codex 跑 10 个原型对比
2. **taste = Seetong 调度能力**：欧阳荣 + 黄松佳等"老登"从"看代码"升级为"看 90 个实现哪个抓住问题"；TAPD 评审从"代码 review"转向"产物阶段标签"
3. **Seetong baby version 试点**：参考"简化版 Cursor/Codex"模式，Seetong 内部建轻量产品代码库快速试 sidebar / pane / chat 交互（如 AI 语义搜索的新交互模式）
4. **Seetong App 升级 = home base**：不重做摄像头 SDK / 4G 模组固件，让 Codex/AI 理解任务 + 调用工具 + 补接口（如 Seetong App 直接调用抖音/微信分享能力，不重做分享 UI）
5. **保存好想法等模型跳一下**：欧阳荣每月"AI 进步观察"笔记，记录暂未实现但值得等模型能力的产品想法（参考 Andrew 的"11 月准备好"案例）
6. **PM 角色不被简化**：黄松佳（产品经理）不能被"所有人都叫 builder"替代；他的工作 = 区域防守 + 把 Seetong 混乱想法引到产品形态（参考 [[03-productivity/Laurel-CPO-Jiaona-Zhang-公司OS]] 的 Captain model）
