一句话总结

实现变便宜后，产品工作的稀缺资源从”工程实现”转向”品味 + 调度能力”——Codex 周活 500 万 / OpenAI 内部 100% 员工用 / 产品流程从 90 份文档倒过来成 90 个原型。

速查表 + Codex 关键数据

核心观点 关键金句 关键数据
产品流程倒过来 “实现已经变便宜了，最贵的是品味。” 90 个原型 vs 90 文档
品味 = 调度能力 “如果什么都能做，目标是什么，我们怎么到达那里。” Paul Graham 工装短裤也有 strong taste

PM 不能取消 “我听过很多公司说要取消产品角色，这在我看来是个很糟糕的想法。” PM 工作 = 区域防守 + 引信号到产品形态
Codex = home base “专业工具继续存在，AI 补一层接口”（Premiere 案例） Codex 给自己写扩展改 Premiere marker

Codex 数据：使用量 1 月以来 6 倍 / 周活 500 万+ / OpenAI 内部 100% 员工用（越过工程团队）/ 核心团队双位数工程师 + 设计 = 工程一半 + 产品人更少 / 团队很多前创始人或”像创始人一样”做事的人。

8 个核心节点 + 3 反直觉点

8 节点：

  1. 产品流程倒过来（90 原型 vs 90 文档）
  2. 品味 = 调度能力 + 系统思考（不是审美）
  3. 选对表达媒介（PRD vs 原型 vs artifact）
  4. baby version 代码库（设计流程一部分）
  5. PM 不能取消（”糟糕的想法”）
  6. Codex = home base（专业工具继续存在 + AI 补接口）
  7. 别和流程绑定，要和结果绑定（等模型跳一下）
  8. Codex 周活 500 万 + OpenAI 100% 员工用

3 反直觉：

  • “实现变便宜”不是”产品变简单”——反而更需要品味 + 调度能力
  • “漂亮原型” ≠ “可发布”——AI 让探索草稿长得很像上线版本；团队要重新给产物贴”阶段标签”
  • “PM 能写代码” ≠ “PM 角色可取消”——产品/设计/工程各自有可学习最佳实践

5 个对 Seetong 借鉴动作 + 6 关联

5 借鉴动作：

  1. Seetong AI Coding 现状体检：哪些走”90 文档”长链、哪些走”90 原型”短链
  2. taste = 调度能力升级：”老登”从”看代码”升级为”看 90 个实现哪个抓住问题”
  3. Seetong baby version 试点：内部建轻量产品代码库快速试 sidebar/pane/chat 交互
  4. Seetong App 升级 = home base：不重做摄像头 SDK，让 AI 理解任务 + 调用工具 + 补接口
  5. PM 角色不被简化：黄松佳（产品经理）不能被”所有人都叫 builder”替代
